# overview

A single identity for every nalet surface — dark canvas, a monospace voice beside the reader's own, blue chevron, square frames — and the components, patterns and rules for building calm, honest admin consoles with it.

> if a screen would look at home in a tmux pane, it is on. if it looks like a saas landing page, start over.

## the identity

The canvas is dark, and only dark: `--bg`, `--bg-2`, `--surface` and `--surface-2`, with four greys of text on top. The `>` chevron is the brand glyph and is always `--cloud-blue`, the same blue as links and the one primary action. JetBrains Mono names things — headings, labels, numbers, codes, the brand — and Inter carries what people read. Every gap comes from one 4-base scale (4, 8, 12, 16, 24, 32, 48, 64), every frame is square, and the words come in two voices: the monospace chrome — titles, buttons, navigation, statuses — is lowercase, and the text people read is in sentence case, in their own language. Both are short, with no emoji and no exclamation marks. There is no light theme today; light and high-contrast themes are **planned**. The details are in [styles](/design-system/styles/) and [content & voice](/design-system/foundations/content-voice/).

## who it is for

- **Admin consoles inside a portal shell.** The main audience: operator tools — lists of things that need doing, settings, status — rendered as federated modules inside one shell's React tree. The library is plain React and CSS: no global styles beyond the tokens and the page base, no provider required, React 18 or 19. See [apps in a shell](/design-system/develop/apps-in-a-shell/).
- **Apps that only need the identity.** A consumer app can take just the tokens — CSS custom properties, typed token objects, or the Tailwind preset — and keep its own components. See [tokens](/design-system/develop/tokens/).
- **The people who design and build them.** Designers start at [designing with it](/design-system/get-started/designing/), developers at [developing with it](/design-system/get-started/developing/).

## how this site is organised

The guidelines live here; the code lives on the [React subsite](/design-system/react/). The six sections in the top bar:

- **Get started** — this page, [designing with it](/design-system/get-started/designing/), [developing with it](/design-system/get-started/developing/), [versioning & changelog](/design-system/get-started/versioning/) and [resources](/design-system/get-started/resources/).
- **Foundations** — the [principles](/design-system/foundations/principles/) every screen follows, and the rules underneath every component: [accessibility](/design-system/foundations/accessibility/), [content & voice](/design-system/foundations/content-voice/), [interaction](/design-system/foundations/interaction/) and [layout](/design-system/foundations/layout/).
- **Styles** — the visual language: [colour](/design-system/styles/colour/) (with the contrast table generated from the tokens), [typography](/design-system/styles/typography/), [iconography](/design-system/styles/iconography/), [shape](/design-system/styles/shape/), [motion](/design-system/styles/motion/) and the [brand](/design-system/styles/brand/).
- **Components** — every component as design guidance, grouped by role. Each page has the same anatomy: when to use it and when not, its parts, variants and states, behaviour, accessibility, content, do and don't, and related pages, with a link to its React implementation. Start at the [components index](/design-system/components/).
- **Patterns** — whole floorplans and the problems that recur across them: the [worklist](/design-system/patterns/worklist/), navigation from the [shell bar](/design-system/patterns/shell-bar/) to the [launchpad](/design-system/patterns/launchpad-and-tiles/), [status vocabulary](/design-system/patterns/status-vocabulary/), [message handling](/design-system/patterns/message-handling/), [empty states](/design-system/patterns/empty-states/), [selection and bulk actions](/design-system/patterns/selection-and-bulk-actions/) and [forms and settings](/design-system/patterns/forms-and-settings/).
- **Develop** — the [React](/design-system/develop/react/) implementation, the [tokens](/design-system/develop/tokens/), [apps in a shell](/design-system/develop/apps-in-a-shell/) and [contributing](/design-system/develop/contributing/).

The [React subsite](/design-system/react/) is the Storybook: every component's playground, its examples, its props and the notes on how it is built. Each guidance page links to its React page, and each React page links back.

## what this site promises

It documents what the code does. Where a component falls short of the principles today, its page says so under "Today:" — a known limitation, not a feature. Where something is coming, it is marked **planned**. A page marked **draft — under review** is a proposal that may still change.
