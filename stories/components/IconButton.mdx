## implementation notes

- It renders a native `<button>`, so the browser gives it the keyboard behaviour for free.
- `type` defaults to `"button"`, not the browser's `"submit"`, so it doesn't send a form by accident. Pass `type="submit"` when it submits a form.
- `label` is required by the type, and becomes the `aria-label` and the native `title`, so the button always has a name and a tooltip.
- A `title` or `aria-label` you pass replaces the one made from `label`.
- The icon is the child you pass, such as `<Icon icon={RotateCw} />`.
- The button doesn't size the icon. The `Icon` default of 16px suits `md`, and the sizes example passes `size={12}` with `sm` and `size={20}` with `lg`.
- `loading` swaps the icon for a spinner, disables the button and sets `aria-busy="true"`. The size doesn't change.
- The spinner has `role="status"` and the name `loading`, but it appears with no text in it, so screen readers may not announce it.
- `disabled` dims it to 45% and takes it out of the tab order.
- A disabled or loading button ignores clicks and can't be focused.
- A focused button shows a 2px `--focus-ring` outline, 1px outside its border, on `:focus-visible`, so the ring shows for keyboard focus and not for a click.
- Every native `<button>` attribute passes through, such as `onClick`, `type` and `aria-*`, and the `ref` reaches the `<button>`.
- `pressed` makes it a toggle button: it sets `aria-pressed`, so a screen reader says “pressed” or “not pressed” after the name. Pass it in both states: `pressed={false}` is a toggle button that is off, and no `pressed` at all is a button that only acts.
- The button holds no state of its own. Keep the state yourself and flip it in `onClick`; if the change fails, set it back.
- The `label` stays the same in both states: the action that turns the button on, such as “save to watchlist”.
- Only `variant="default"` and `variant="ghost"` can be on. `primary` and `danger` ignore `pressed` and render no `aria-pressed`, so a screen reader never hears a state the screen doesn't show.
- An `aria-pressed` you pass yourself does what `pressed` does; `pressed` wins when both are given.
- The on look is drawn from `aria-pressed="true"`: a `--surface-selected` fill and a 2px `--cloud-blue` inset shadow along the bottom edge. The size doesn't change.
- Inside an element with `data-nc-screen="touch"`, every icon button is 42px square whatever its `size`, an icon passed as a direct `svg` child is drawn at 20px, and an `::after` of at least 48 × 48, centred on the button, takes touches around it. The button becomes `position: relative` for that.
- Inside an element with `data-nc-screen="tv"`, every icon button is 42px square and shows the TV focus on `:focus-visible`: a 3px `--focus-ring` outline 2px outside, the `--surface-focus` fill on every variant but `primary`, and a scale of 1.05, which reduced motion turns off.

| key | does |
| --- | --- |
| `tab` / `shift+tab` | Moves focus to / from the button. |
| `enter` / `space` | Activates it. With `pressed`, your `onClick` turns it on or off, and focus stays on the button. |
