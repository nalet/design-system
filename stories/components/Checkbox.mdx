## implementation notes

- Renders a `<label>` around the box and the label text. The native `<input type="checkbox">` lies over the box, transparent. It takes the focus, the clicks and the form value. The control is a native checkbox, so the browser provides the keyboard model.
- The component holds no state. Use `defaultChecked`, or `checked` with `onChange`.
- `indeterminate` is yours to control: in `onChange`, set the parent's `checked` when all children are on, and `indeterminate` when only some are.
- `aria-checked="mixed"` comes from the native `indeterminate`, which the component sets on the `<input>`. The browser clears the mixed state on every click, and the component re-applies `indeterminate` only when the prop changes. Recompute it in `onChange`, as the parent example above does.
- Focus is drawn on `:focus-visible`.
- `enter` does not toggle a checkbox.
- `className` lands on the outer `<label>`; every other attribute — `checked`, `defaultChecked`, `onChange`, `name`, `value`, `aria-*` — and the ref land on the native `<input type="checkbox">`.
- Today: if `indeterminate` stays `true` across a click, the dash stays drawn but the browser's mixed state is gone, so assistive tech announces on or off while the screen shows mixed.
- Today: inside a [field](?path=/docs/components-inputs-field--docs) with `error`, `aria-invalid` is set on the native checkbox, and React warns about an unknown `invalid` attribute.

| key | does |
| --- | --- |
| `tab` / `shift+tab` | Moves focus to / from the checkbox. |
| `space` | Toggles it. On a mixed box this also clears the mixed state. |
