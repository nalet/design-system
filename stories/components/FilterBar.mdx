import { Meta, Canvas, ArgTypes } from '@storybook/addon-docs/blocks';

import { FilterBar } from '../../src';
import { DoDont, Do, Dont } from '../_blocks';

export const DemoBar = ({ label, noun, total, facet, options, initial = '', count = true }) => {
  const [q, setQ] = useState('');
  const [value, setValue] = useState(initial);
  const set = (q ? 1 : 0) + (value ? 1 : 0);
  const left = Math.max(1, Math.round(total / (1 + set * 3)));
  return (
    <FilterBar
      label={label}
      search={{ value: q, onChange: setQ, placeholder: `search ${noun}`, label: `search ${noun}` }}
      filters={[{ type: 'select', id: facet, label: facet, value, onChange: setValue, options }]}
      resultCount={count ? (set ? `${left} of ${total}` : String(total)) : undefined}
      onClearAll={() => {
        setQ('');
        setValue(initial);
      }}
    />
  );
};

# filter bar

what narrows a list: a search field, facets that keep one value (a select) or several (a multi select), `clear all`, and the count of what is left. it is fully controlled: the list filters itself from the values. on a narrow screen the facets fold behind one `filters` toggle.

<Canvas of={FilterBarStories.Playground} />

## when to use

- above a list or a table, for the search and the two to four facets that narrow it.
- with the result count — `312 of 2,500` — so people see the filters work, and screen-reader users hear it.
- under [filter tabs](?path=/docs/components-navigation-filter-tabs--docs) and above the [toolbar](?path=/docs/components-actions-toolbar--docs), the way the [worklist](?path=/docs/patterns-worklist--docs) arranges them.

## when not to use

- **for a few key figures that each pick one subset.** use [filter tabs](?path=/docs/components-navigation-filter-tabs--docs).
- **to sort.** sort with the column headers of the [data table](?path=/docs/components-data-display-data-table--docs).
- **for a form that is submitted** — settings, a new item. use [fields](?path=/docs/components-inputs-field--docs) and a save button, as in [forms and settings](?path=/docs/patterns-forms-and-settings--docs). the filter bar filters as values change and submits nothing.
- **for actions on the list.** use a [toolbar](?path=/docs/components-actions-toolbar--docs).

## anatomy

1. **container** — `role="search"`, named by `label` (default "filters"): a flex row that wraps, with 8px × 12px gaps.
2. **search** (optional) — an `<input type="search">`, 34px tall, with a square search glyph in front. it starts at 240px and grows or shrinks between 180 and 420px.
3. **facets** — a `select` facet is a visible label (jetbrains mono 12px, `--fg-muted`, lowercase) and a native [select](?path=/docs/components-inputs-select--docs), at least 128px wide; while it filters, its value shows in `--cloud-blue`. a `multiselect` facet is a [multi select](?path=/docs/components-inputs-multi-select--docs) at `md`.
4. **children** (optional) — your controls, after the facets. they fold with them.
5. **end** — pushed to the right: the result count (jetbrains mono 12px, `--fg-muted`, tabular figures) and `clear all`, a ghost `md` button. on a narrow bar, `clear all` moves to the end of the folded facets.
6. **filters toggle** (narrow only) — a default `md` button: `filters`, or `filters · 2` while two facets are set.

## variants and states

wide, the bar is one row that wraps when it has to.

below `collapseBelow` — 640px by default, measured on the bar itself — the facets fold behind the `filters` toggle. the search and the toggle share the first line; the facets open in a column under them, with `clear all` at their end; the count keeps a line of its own, and takes no room while there is no count. until the bar has been measured, and wherever there is no `ResizeObserver`, it lays out wide. the toggle counts the facets that are set, not the search.

a facet is **set** while it filters: a `select` whose value isn't its `emptyValue` (`""` by default), a `multiselect` with anything chosen. `clear all` is enabled while any facet is set or the search holds text, and disabled otherwise.

## behaviour and keyboard

the bar holds no values of its own. each value comes from you and goes back through its `onChange`; the list filters itself from them.

| key | does |
| --- | --- |
| `tab` / `shift+tab` | native order: the search, each facet, your controls, `clear all`. narrow: the search, the `filters` toggle and, while it is open, the facets, your controls and `clear all`. a disabled `clear all` is skipped. |
| typing in the search | calls `search.onChange` on every keystroke: the list filters as the person types. |
| `esc` in the search | clears it, when it holds text. a modal around the bar stays open. on an empty search, the key goes on to the page. |
| keys in a select facet | native: see [select](?path=/docs/components-inputs-select--docs). |
| keys in a multi select facet | see [multi select](?path=/docs/components-inputs-multi-select--docs). |
| `enter` / `space` on the `filters` toggle | shows or hides the facets. |

- `clear all` calls `onClearAll`. reset the search and every facet there.
- the `filters` toggle starts closed and keeps its state while the bar is on the page.

## accessibility

- the bar is a `search` landmark named by `label` (default "filters"), so screen-reader users can jump to it. with two filter bars on one page, give each its own `label`.
- the search field is named by `search.label` (default "search"), as an `aria-label`. the placeholder is only a hint: it is gone with the first keystroke.
- each `select` facet sits inside its own `<label>`, so the facet's label is its name: "kind".
- **the result count is live**: `aria-live="polite"` with `aria-atomic="true"`, so each change is read whole — "312 of 2,500" — when the screen reader has a pause. the region is always on the page, empty while there is no `resultCount`, so the first count is announced too. it is how someone typing hears that the list changed, also when it is left empty.
- narrow, the toggle has `aria-expanded`, and `aria-controls` pointing at the facets. folded facets are `hidden`, out of the tab order.
- axe-core finds no violations, with a multi select open.

- `clear all` disables itself once everything is clear, so it moves focus to the search field first.

today:

- narrow, `clear all` folds with the facets, so it can be reached only once `filters` is open.
- `clear all` and `filters` are fixed english and can't be translated.
- `clear all` only knows the search and the facets in `filters`. a control in `children` doesn't enable it.
- narrow, a bar with `children` or `onClearAll` but no `filters` shows no toggle: the children and `clear all` stay folded away, with no way to open them.

## content

- **search** — the placeholder says what can be searched, `search titles`. give `search.label` the same words.
- **facet labels** — a noun: `kind`, `aired`, `state`.
- **the no-filter option** — first in every select, in plain words: `all`, `any time`. its value is the facet's `emptyValue`.
- **result count** — what is left, of what: `312 of 2,500`, with thousands separators. while nothing filters, the total (`2,500`), or nothing.
- two to four facets. with more, the bar turns into a form.

## props

`FilterBar` passes other `<div>` attributes and its `ref` to the `role="search"` element.

<ArgTypes of={FilterBarStories} />

`search` takes `value`, `onChange`, `placeholder` and `label` (default "search"). each entry in `filters` is one facet:

| field | `select` facet | `multiselect` facet |
| --- | --- | --- |
| `type` | `"select"` | `"multiselect"` |
| `id` | a key, unique in the bar | the same |
| `label` | the facet's name, shown before the select | the multi select's label |
| `value` | a string | an array of strings |
| `onChange` | gets the new string | gets the new array |
| `options` | `value` and `label`, the no-filter option first | `value`, `label` and an optional `count` |
| `emptyValue` | the value that means no filter, default `""` | — |
