# the nalet design system

a single identity for every nalet surface — dark canvas, monospace voice, blue chevron, square frames — and the components, patterns and rules for building calm, honest admin consoles with it.

> if a screen would look at home in a tmux pane, it is on. if it looks like a saas landing page, start over.

## principles

five rules decide every component and every page here. when two pull apart, the earlier one wins.

1. **calm.** a screen shows what is true and what to do next, and little else. no decoration, no motion that isn't feedback, no colour that doesn't mean something. quiet is the default; attention is earned.
2. **honest status.** every object has one status, said once, in its own words, from one table. a warning never renders green, a failure is never hidden to keep a list looking healthy, and something that can't be known says so instead of looking empty. see [status vocabulary](?path=/docs/patterns-status-vocabulary--docs).
3. **one emphasized action.** a view, a toolbar or a dialog has at most one primary button — the next step. everything else is a default button, a ghost button or a menu item. per-row actions live in one menu per row; bulk actions in the selection toolbar.
4. **keyboard first.** everything works without a pointer, and composite widgets (tabs, toolbars, tables, the launchpad) take one tab stop and move with the arrow keys. focus is always visible and always returns where it came from.
5. **accessible by default.** the right roles, names and live regions are built in, so the obvious way to use a component is the accessible way. every text colour meets wcag 2.2 aa on every background, and a test keeps it so. see [accessibility](?path=/docs/foundations-accessibility--docs).

## who it is for

- **admin consoles inside a portal shell.** the main audience: operator tools — lists of things that need doing, settings, status — rendered as federated modules inside one shell's react tree. the library is plain react and css: no global styles beyond the tokens and the page base, no provider required, react 18 or 19.
- **apps that only need the identity.** a consumer app can take just the tokens — css custom properties, typed token objects, or the tailwind preset — and keep its own components.

## the non-negotiables

- **dark canvas only** — `--bg`, `--bg-2`, `--surface`, `--surface-2`. there is no light theme today (it is planned).
- **the `>` chevron is the brand glyph** and is always `--cloud-blue`. links and the primary action share that blue.
- **type** — jetbrains mono for display, headings, labels, numbers, codes and the brand; inter for body and prose.
- **space** — a 4-base scale: 4, 8, 12, 16, 24, 32, 48, 64.
- **square frames** — `border-radius: 0` on every card, panel, button, input and dialog. icons are the only rounded shape.
- **voice** — lowercase, short, no emoji, no exclamation marks. see [voice & content](?path=/docs/foundations-voice-content--docs).
