## implementation notes

- It renders a native `<textarea>`, and the box you see is that element itself, so the browser gives it the keyboard behaviour for free.
- The component holds no state of its own. Use `defaultValue`, or `value` with `onChange`.
- A [field](?path=/docs/components-inputs-field--docs) renders a `<label for>` for it and links the hint or error with `aria-describedby`.
- `invalid` sets `aria-invalid="true"` and the `--state-error` border. A field's `error` sets `invalid` for you.
- For read-only, use the native `readOnly`.
- The length limit is the native `maxLength`. Link a count to the textarea with `aria-describedby`, as the controlled example does, so a screen reader reads the count with the field.
- Every native `<textarea>` attribute passes through (`value`, `onChange`, `maxLength`, `name`, `aria-*`, …), and the ref reaches the `<textarea>`.

| key | does |
| --- | --- |
| `tab` / `shift+tab` | Moves focus to / from the field. `tab` does not type a tab character. |
| `enter` | Starts a new line. It never submits the form. |
| Arrows, `home`, `end` | Move the caret. With `shift`, they select. |
