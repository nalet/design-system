# box

## implementation notes

- It renders a `div` with `box-sizing: border-box` and `border-radius: 0`, so padding and border stay inside the width you set, and the corners stay square.
- `p` pads every side, `px` the left and right, and `py` the top and bottom.
- Each takes 0, 4, 8, 12, 16, 24, 32, 48 or 64 and resolves to the `--s-1` … `--s-8` tokens, so the padding always comes from the space scale.
- `px` and `py` are applied after `p`, so they win: `p={16} px={24}` gives 16px top and bottom and 24px left and right.
- `p`, `px`, `py` and `bg` are written as inline styles on top of your `style`, so they win over the same properties there.
- Today: when `p` changes on a re-render while `px` or `py` is set, the new `padding` shorthand can overwrite the sides that `px` or `py` set, and React warns about this in development. When the padding changes at run time, use `p` alone, or `px` and `py` together.
- The `div` has no role. To make the box a landmark or a region, pass a `role` with `aria-label` or `aria-labelledby` through, or use a native element.
- Today: it is always a `div`. There is no `as` prop to render a `section`, an `aside` or a `ul`.
- Every native `div` attribute passes through, and the `ref` reaches the `div`.
