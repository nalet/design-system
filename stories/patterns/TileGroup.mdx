# tile group

a titled section of [tiles](?path=/docs/components-navigation-tile--docs) in a square grid. the group is one tab stop; the arrow keys move between its tiles.

<Canvas of={TileGroupStories.Playground} />

## when to use

- to gather tiles under a stable name on a launchpad: `operations`, `media`, `admin`.
- on its own, for a short set of destinations on a hub page.
- to line up a few kpi tiles as a row of key figures.

## when not to use

- **for a whole launchpad with search and favourites.** use the [portal](?path=/docs/patterns-portal--docs); it holds tile groups and runs one keyboard model across all of them.
- **for records, or anything people compare row by row.** use a [data table](?path=/docs/components-data-display-data-table--docs).
- **for a single tile.** a lone [tile](?path=/docs/components-navigation-tile--docs) needs no section around it.
- **for panels of text and controls.** use [cards](?path=/docs/components-layout-structure-card--docs) in a [stack](?path=/docs/components-layout-structure-stack--docs).

## anatomy

1. **section** — a `<section>` named by its legend.
2. **legend** — an `<h2>` led by a 14px brand chevron: jetbrains mono 600, 13px, letter-spacing 0.04em, `--fg-muted`, shown lowercase.
3. **action** (optional) — a slot at the right end of the legend row, 12px from the legend.
4. **description** (optional) — a `<p>` under the legend: inter 13px in `--fg-dim`.
5. **grid** — a css grid of tiles, 12px below the legend row or the description.

## variants and states

`columns="auto"` (the default) fits as many columns as there is room for at `minTileWidth` (default 14rem, 224px at a 16px root) and stretches them evenly, so the grid reflows with the width. a number fixes the column count at every width.

<Canvas of={TileGroupStories.FixedColumns} />

`gap` sets the space between tiles: `xs` 4px, `sm` 8px, `md` 16px (the default), `lg` 24px.

`action` takes one low-weight control for the group as a whole; `description` adds a line under the legend.

<Canvas of={TileGroupStories.WithAction} />

<Canvas of={TileGroupStories.WithDescription} />

`navigation` picks the keyboard model: `roving` (the default; one tab stop and the arrow keys) or `tab` (every tile is its own tab stop).

<Canvas of={TileGroupStories.TabOrder} />

a group with the `hidden` attribute disappears; the portal's search hides groups that way when none of their tiles match.

## behaviour and keyboard

with `navigation="roving"`:

| key | does |
| --- | --- |
| `tab` / `shift+tab` | enters the group on one tile and leaves it on the next press. that tile is the one you last moved to with the arrow keys, otherwise the first enabled tile. |
| `→` / `←` | the next / previous tile in reading order. stops at the first and the last tile. |
| `↓` / `↑` | the nearest tile below / above by position on screen, preferring the same column. |
| `home` / `end` | the first / last tile. |
| `enter` / `space` | native: `enter` follows a link tile; `enter` and `space` press a button tile. |

- the keys act only while focus is on a tile in the grid. the action slot keeps its own tab stop.
- the arrow keys skip disabled and display-only tiles (they aren't links or buttons) and tiles that aren't visible.
- inside a [portal](?path=/docs/patterns-portal--docs) that runs roving (its default), the group leaves the keys to the portal, and they move across all groups.
- with `navigation="tab"`, every tile is its own tab stop and the arrow keys do nothing.

## accessibility

- the group is a `<section>` labelled by its legend, so it is a region landmark that people can jump to.
- the legend is a real `<h2>`; the chevron before it is `aria-hidden`.

today:

- the legend is always an `<h2>`, whatever the headings around it; there is no prop for another level.
- nothing tells screen-reader users that the arrow keys move between tiles: the grid has no role that announces it. with roving on, `tab` reaches one tile per group, while a screen reader's browse mode still reads every tile. if people get stuck, use `navigation="tab"`.

## content

- **legend** — a noun for what the tiles are for, one or two words: `operations`, `media`, `admin`. not `misc`, `other` or `apps`.
- **description** — only when the legend needs it, as one short sentence.
- **action** — one action about the group as a whole (`manage`), as a ghost button.
- order the tiles the way people think about them, and keep that order. don't reorder by use: people find tiles by where they were.
