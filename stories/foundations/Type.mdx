# typography

two families and six roles. jetbrains mono names things: headings, titles, labels, values, numbers and code. inter carries what people read: prose, hints, messages and interface text.

<Canvas of={TypeStories.Scale} sourceState="none" />

## the two families

| token | family | stack | for |
| --- | --- | --- | --- |
| `--ff-mono` | jetbrains mono | `'JetBrains Mono', ui-monospace, monospace` | headings and titles, the labels of buttons, tabs, menus and table headers, badges and status, toasts and tooltips, what people type into fields, numbers, code |
| `--ff-ui` | inter | `Inter, system-ui, sans-serif` | body copy, field labels, hints and errors, checkbox and switch labels, message strips, secondary lines |

`tokens.css` sets `font-family: var(--ff-ui)` on `body`, so anything that sets no family of its own is inter.

## the roles

the roles live in `tokens/tokens.json` (`type.role`). the specimen above is drawn from the same values.

| role | family | weight | size / line height | letter-spacing | in components |
| --- | --- | --- | --- | --- | --- |
| `display` | mono | 800 | 56px / 1.00 | -0.030em | none. a splash or a sign-in screen, through `.type-display` |
| `h1` | mono | 700 | 32px / 1.15 | -0.015em | [heading](?path=/docs/components-layout-structure-heading--docs) `level={1}` |
| `h2` | mono | 600 | 22px / 1.20 | 0 | heading `level={2}` |
| `body` | inter | 400 | 16px / 1.55 | 0 | [text](?path=/docs/components-data-display-text--docs) `variant="body"` |
| `ui` | inter | 500 | 13px / 1.40 | 0 | text `variant="ui"`, the [field](?path=/docs/components-inputs-field--docs) label |
| `code` | mono | 500 | 13px / 1.50 | 0 | text `variant="code"` |

- there is no `h3` role. a sub-section gets a native `h3` through text: `as="h3"`, as the heading page says.
- the components also use sizes between the roles, set in their own css: 11px (badges, object status, table headers), 12px (`sm` buttons, hints and errors, tooltips, dates, counts), 14px (`lg` buttons and fields, the modal body, tile titles), 15px (modal titles), 20px (filter tab counts), 22px at 700 (the worklist and portal titles) and 28px (a tile's key figure). they are not tokens: use them through the components, not in your own css.
- the largest mono is drawn tighter: display −0.03em, `h1` −0.015em, the portal title and the filter tab counts −0.01em. small mono labels are opened up: 0.04em on table headers, tile group legends and divider labels, 0.02em on badges and object status.

## weights

<Canvas of={TypeStories.Weights} sourceState="none" />

- most mono values set no weight: inputs, code, badges, toasts, tooltips and the cells of the plain [table](?path=/docs/components-data-display-table--docs) take the weight of the text around them, 400 on a plain page.
- 600 marks a label that names something (a button, a title, a column); 700 is for the page title and a key figure. inter is 400 for reading and for checkbox and switch labels, 500 for field labels and `ui` text.

## lowercase

- the voice is lowercase. many components also set `text-transform: lowercase`: buttons, tabs and filter tabs, menu items, badges and object status, table headers, field labels, the labels of the filter bar and multi select, divider labels, and the titles of cards, modals, tiles, toolbars, tile groups, worklists, the portal and illustrated messages.
- the transform changes the look, not the text: the dom keeps what you wrote. browsers differ in which of the two they hand to assistive tech, so write the source the way it should be read, lowercase, and both say the same.
- headings, body text, hints and errors, checkbox and switch labels, message strips, toasts, tooltips and the values in fields have no transform. capitals you write there show.
- names that are content keep their case: an identifier cell, the label of a data table group, a title quoted in a sentence. a card, tile or modal title is lowercased even when it holds a name, so a name that must keep its case goes in the body.

## numbers

- numbers that people compare, count or watch change are mono: counts, sizes, dates, durations, ids. every mono glyph has the same width, so a column of numbers lines up and a count that changes doesn't push its neighbours.
- the counts in the components also set `font-variant-numeric: tabular-nums`: filter tab counts, the filter bar's result count, multi select option counts, a tile's key figure, delta and count badge, the growing row of a data table, and the date cell.
- a number inside an inter sentence stays inter. in an inter column or a value that updates in place, add `font-variant-numeric: tabular-nums`.
- counts carry a thousands separator. `formatCount(2500)` gives `2,500`; it is the formatter the components use.

## loading the fonts

the library does not ship or load the fonts. `tokens.css` names them in `--ff-ui` and `--ff-mono` but has no `@font-face`. until they load, or if they never do, text falls back to the rest of each stack: `system-ui`, then `sans-serif`; `ui-monospace`, then `monospace`.

load them once, in the app's global css or its html. this is the line the storybook itself uses, in `.storybook/preview.css`:

```css
@import url('https://fonts.googleapis.com/css2?family=Inter:wght@400;500;600;700&family=JetBrains+Mono:wght@400;500;600;700;800&display=swap');
```

- a `<link rel="stylesheet">` with the same url in the `<head>` starts the download sooner than an `@import`. an `@import` must come before every other rule in its stylesheet.
- to self-host, declare the files with `@font-face` under the family names `Inter` and `JetBrains Mono`, exactly: the stacks look for those names.
- load jetbrains mono 400. it is the weight most mono values are drawn in. the `@import` suggested in the comment at the top of `tokens.css` starts at 500, and with it every 400 value renders at 500.
- the components draw inter at 400 and 500 only; 600 and 700 are there for bold text in your own content. jetbrains mono 800 is only for the display role.
- `display=swap` shows the fallback first and swaps the font in when it arrives.

## how to apply it

- **components first.** [heading](?path=/docs/components-layout-structure-heading--docs), [text](?path=/docs/components-data-display-text--docs), [code](?path=/docs/components-data-display-code--docs) and [kbd](?path=/docs/components-data-display-kbd--docs) carry the roles; every other component sets its own type.
- **role classes.** `tokens.css` defines `.type-display`, `.type-h1`, `.type-h2`, `.type-body`, `.type-ui` and `.type-code`: family, weight, size, line height and letter-spacing. no colour, no margin.
- **css variables.** the families are `var(--ff-mono)` and `var(--ff-ui)`. sizes and weights are not variables.
- **typescript.** `typography.h1` and `fontFamily.mono` come from `@nalet/design-system` (or `@nalet/design-system/tokens`): the same metrics as objects, ready to spread into a `style`.
- **tailwind.** the preset maps `font-mono` and `font-sans` to the two stacks. it adds no font sizes.

## accessibility

- the lowercase look is css, and assistive tech may get either the written or the transformed text. written lowercase, the two are the same.
- don't let a family, a weight or a size carry meaning on its own. a state is [object status](?path=/docs/components-feedback-status-object-status--docs), with words and a glyph; a structure is a real heading.
- today: every size is in px. text grows with the browser's zoom, but not with a larger default font size set in the browser's settings.
- today: the role classes in `tokens.css` write the font stacks out instead of using `var(--ff-ui)` and `var(--ff-mono)`, so overriding a family variable doesn't reach them.
