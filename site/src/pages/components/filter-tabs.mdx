# filter tabs

Key figures that filter one list: each tab is a count over a label — `3` over `needs attention` — and choosing a tab filters the list below it. A tab list with one tab stop, where the arrow keys select as they move.

    <Playground client:visible />
  </div>
</Example>

## when to use

- At the top of one list, to show the few subsets people act on and let them pick one: `missing`, `on their way`, `needs attention`.
- When each subset's count is worth seeing before choosing it.
- For one subset at a time, from two to about six. The [worklist](/design-system/patterns/worklist/) puts them over its table.

## when not to use

- **To switch between views of one object** — overview, logs, metrics. Use <C slug="tabs" />.
- **For filters people combine** — a kind, and a time, and a state. Use the facets of a <C slug="filter-bar" />, which combine.
- **For a figure that filters nothing.** Show the number as text, or as a <C slug="badge" /> beside what it counts.
- **To go to another page.** Use a link.

## anatomy

1. **Tab list** — a row with a 1px `--border` rule under it. When the tabs don't fit, the row scrolls sideways, and the edge where more tabs are cut off fades out over 48px.
2. **Tab** — at least 96px wide, 8px 16px 12px padding, JetBrains Mono, left-aligned. The count sits on top, but the label is read first: "needs attention 3".
3. **Count** (optional) — 20px, weight 600, tabular figures, with thousands separators (`2,500`), in `--fg` or in the colour of the tab's state.
4. **Label** — 12px, weight 500, lowercase, one line, in `--fg-muted`; `--fg` on hover and when selected.
5. **Selection** — a 2px `--cloud-blue` underline, laid over the row's rule.
6. **Panel** — yours: the list the tabs filter. It isn't part of the component; how it is named is under [accessibility](#accessibility).

## variants and states

| state | looks |
| --- | --- |
| Rest | Label in `--fg-muted`; count in `--fg` or in its state's colour |
| Hover | `--surface` fill, label in `--fg` |
| Selected | Label in `--fg`, 2px `--cloud-blue` underline |
| Focus | A 2px `--focus-ring` outline inside the tab |
| Disabled | 45% opacity. It can't be focused, chosen or reached with the arrow keys |

### states on counts

A state colours the count, and only the count, when the number carries a meaning: `error` for `needs attention`, `warning` for `can't be checked`, `information` for `on their way` (the colours of the [status vocabulary](/design-system/patterns/status-vocabulary/)). Leave it off for counts that only say how many, `missing` or `not yet aired`: they stay plain `--fg`. A tab without a count shows no state at all. The example at the top uses both.

Leave the count out when the number isn't known; the tab then shows its label alone.

## behaviour

- A click selects a tab.
- Automatic activation: the selection follows focus, so every arrow press filters the list. Keep the filtering quick — it is usually local — or let a slow list settle before it loads.

The keyboard map and the attributes it sets are on its [React page](/design-system/react/?path=/docs/components-navigation-filter-tabs--docs).

## accessibility

- The tab list has a name, and it is required: what it filters, and by what — `filter missing by state`. Only the selected tab is in the tab order.
- A tab's name is its label, then its count: "needs attention 3".
- The list below is the tabs' panel, named after the selected tab: "needs attention 3".
- The state colour on a count is a second signal: the label says what the count means. A count has no glyph, unlike an <C slug="object-status" />, so never let the colour say what the label doesn't.
- A count that changes is not announced.

Today:

- Disabled tabs can't be focused, so screen-reader users don't learn that they exist.

## content

- **Label** — what the tab keeps, in the list's words: `needs attention`, `on their way`, `can't be checked`. A few words, lowercase.
- **Count** — exact, never rounded. Leave it out when it isn't known, rather than showing `0`.
- **First tab** — the whole list, `missing` or `all`, so there is always a way back.
- **The tab list's name** — what it filters, and by what: `filter missing by state`.
