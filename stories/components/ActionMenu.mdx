# action menu

actions behind one trigger: a menu button and a menu of verbs, rendered into `document.body` so no table cell or panel cuts it off. use one per table row, and as the overflow of a toolbar.

<Canvas of={ActionMenuStories.InARow} />

## when to use

- for the actions on one object, behind one trigger per row: `pick a release`, `grab now`. one menu per row keeps a table calm.
- for the overflow of a toolbar. the [toolbar](?path=/docs/components-actions-toolbar--docs) puts what doesn't fit behind `more actions` itself.
- for a few related commands behind a text trigger: `export`, then `as csv` or `as json`.

## when not to use

- **for the one emphasized action of a view.** show it as a [button](?path=/docs/components-actions-button--docs); in a menu, nothing reads as the next step.
- **for actions on several selected rows.** use a [selection toolbar](?path=/docs/components-actions-toolbar--docs), which says how many it acts on.
- **to choose a value** — a sort order, a filter. a menu runs commands and doesn't show the current choice. use a [select](?path=/docs/components-inputs-select--docs), or a [multi select](?path=/docs/components-inputs-multi-select--docs) for several values.
- **to go to another page.** use a link. a menu item is a button, and can't be opened in a new tab.
- **to ask for a decision.** use a [modal](?path=/docs/components-overlays-modal--docs).

## anatomy

1. **trigger** — by default a ghost [icon button](?path=/docs/components-actions-icon-button--docs) with three 2.5px squares: 28px square at `sm` (the default), 34px at `md`. with `buttonLabel`, a default button with your text and a trailing chevron.
2. **menu** — rendered into `document.body`: `position: fixed`, `z-index: 150`, `--surface` fill, a 1px `--border-2` frame, square corners, 4px of padding above and below, and a shadow. at least 160px wide, or as wide as the trigger if that is wider; never wider than the viewport minus 16px.
3. **item** — a button with `role="menuitem"`: at least 32px tall, 4px × 12px padding, jetbrains mono 13px in `--fg-2`, lowercase, on one line. hover and focus give it `--surface-2` and `--fg`; keyboard focus adds a 2px `--focus-ring` bar on its left edge.
4. **item icon** (optional) — decoration before the label, in `--fg-muted`.

## variants and states

the trigger is the icon (default) or a text label (`buttonLabel`). use the icon in a row, where the row already names the object; use text where the trigger stands on its own.

<Canvas of={ActionMenuStories.Playground} />

<Canvas of={ActionMenuStories.TextTrigger} />

an item can be `disabled` — 45% opacity, it can't be run and the arrow keys skip it — or `danger`, for an action that deletes or can't be undone: its label stays `--signal-amber` at rest, on hover and on focus. put danger items last.

<Canvas of={ActionMenuStories.DisabledAndDanger} />

`loading` puts a spinner in the trigger, sets `aria-busy` and keeps the menu from opening. `disabled` turns the whole menu off. both disable the trigger, so it can't be focused.

<Canvas of={ActionMenuStories.Busy} />

`size` sets the trigger: `sm` (28px, the default) for table rows and toolbars, `md` (34px) next to other `md` controls.

### positioning

the menu renders into `document.body`, so no table cell, scroll container or panel with `overflow: hidden` cuts it off. it opens 4px under the trigger. when it wouldn't fit below (it would come within 8px of the viewport's bottom edge) and there is room above, it opens above. `align` lines up its `end` edge with the trigger's (the default) or its `start` edge, and it always keeps 8px from the viewport's left and right edges. while it is open it follows the trigger when anything scrolls or the window resizes. it is measured before it shows, so it never flashes in the wrong place.

## behaviour and keyboard

the trigger is a menu button: it opens a menu, which holds the focus until it closes.

| key | does |
| --- | --- |
| `enter` / `space` on the trigger | opens the menu and focuses its first item that isn't disabled. |
| `↓` on the trigger | the same: opens on the first item. |
| `↑` on the trigger | opens on the last item. |
| `↓` / `↑` in the menu | moves to the next / previous item, wrapping at the ends. disabled items are skipped. |
| `home` / `end` | moves to the first / last item. |
| `enter` / `space` on an item | closes the menu, puts focus back on the trigger, then runs the item. |
| `esc` | closes the menu and puts focus back on the trigger. the key goes no further, so a modal around the menu stays open. |
| `tab` / `shift+tab` | closes the menu, and focus moves on from the trigger as if the menu had not been there. |

- a click on the trigger opens or closes the menu. a press anywhere outside the menu and its trigger closes it; focus stays where that press put it.
- a click on a disabled item does nothing, and the menu stays open.
- `onOpenChange(open)` is called when the menu opens and when it closes.
- focus is back on the trigger before an item's `onSelect` runs, so a [modal](?path=/docs/components-overlays-modal--docs) opened by the item returns focus there when it closes.

## accessibility

- the trigger has `aria-haspopup="menu"`, `aria-expanded`, and `aria-controls` pointing at the menu while it is open. the menu has `role="menu"` and takes its name from the trigger (`aria-labelledby`). the items are buttons with `role="menuitem"` and `tabindex="-1"`: inside the menu, the arrow keys move.
- **name the object, not the action.** the icon trigger's name is `label`, which is also the browser's own tooltip: `actions for S04E07`, `actions for worker-2`. a table whose fifty triggers are all called "more" gives a screen-reader user fifty buttons they can't tell apart.
- **with `buttonLabel`, the visible text is the name**, and `label` isn't used: what people see is what speech-input users say (wcag 2.5.3, label in name). `label` is still required by the type, so pass the same words.
- disabled items keep `aria-disabled="true"` and stay in the menu.
- danger is a colour only. the label has to say what happens (`delete worker`); for what can't be undone, ask in a [modal](?path=/docs/components-overlays-modal--docs) once the item is chosen.
- item icons are hidden from assistive tech.
- axe-core finds no violations, closed or open.

today:

- the arrow keys skip disabled items, so a keyboard user never lands on one and may not learn that it exists, or why it is off. say the reason on the page, in the row's status.
- no type-ahead: typing a letter doesn't move to the item that starts with it.
- no separators or groups inside the menu.
- there are no forced-colours (windows high contrast) styles. a focused item shows only a fill and an inset bar, and forced colours remove both.

## content

- **items** — a verb and its object, lowercase: `pick a release`, `grab now`, `open logs`, `delete worker`.
- **order** — the most used first; danger last.
- **the same shape on every row** — in a list, disable an item that doesn't apply to a row rather than leaving it out, and let the row's status say why.
- **the icon trigger's `label`** — `actions for` and the object's name as the row shows it: `actions for S04E07`.
- **a text trigger** — one or two words for what is behind it: `export`.

## props

`ActionMenu` passes no other attributes through; `className` goes on the trigger.

<ArgTypes of={ActionMenuStories} />

each entry in `items`:

| field | does |
| --- | --- |
| `id` | a key, unique within the menu |
| `label` | the item's text: a verb and its object |
| `onSelect` | runs once the menu has closed and focus is back on the trigger |
| `disabled` | stays in the menu, can't be run, and the arrow keys skip it |
| `danger` | the label in `--signal-amber`: deletes, or can't be undone |
| `icon` | decoration before the label |
