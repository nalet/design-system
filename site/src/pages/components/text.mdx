# text

Text sets a run of words in one of five <Term id="type-role">type roles</Term>: body text for reading, interface text for short names and values, muted and dim text for secondary lines, and mono text for values.

<Example label="the five type roles">
  <Variants />
</Example>

## when to use

- For sentences and paragraphs: body text, set as a paragraph.
- For short text in an interface that isn't a control's own label, such as a name in a list or a value in a panel: interface text.
- For secondary facts beside the main line, such as a timestamp, a size or a path: muted text. For a line people can safely skip: dim text.
- For values people read in <Term id="monospace">monospace</Term>, such as durations, hashes and sizes, when they don't need the frame that <C slug="code" /> draws: mono text.
- For a line that must not wrap, such as a long path in a narrow column: text cut to one line.

## when to use something else

- **For a page or section title.** Use a <C slug="heading" />, which makes a real heading, at the first or the second <Term id="heading-level">heading level</Term>.
- **For commands, flags or anything people type or copy.** Use <C slug="code" />, which marks the text as code and puts it in a frame.
- **For a keyboard key.** Use <C slug="kbd" />, which draws the key as a keycap.
- **For a form label, a hint or an error.** Use a <C slug="field" />. It makes a real label, ties the hint and the error to the control, and marks the control as invalid. Text that only looks like a label is styled text, tied to nothing.
- **For a state or a message.** The state of an object is an <C slug="object-status" />; a message about the page is a <C slug="message-strip" />.

## anatomy

1. **Run of text.** Words in one role, with no space of their own around them. The role sets the typeface, the weight, the size, the spacing between lines and the colour.
2. **<Term id="ellipsis">Ellipsis</Term>** (when it is cut to one line). Three dots where the line is cut, at the edge of its container.

## variants and states

### the five roles

| role | looks | use it for |
| --- | --- | --- |
| Body text (the default) | The <Term id="body-face">body face</Term> at reading size, in a soft white | Sentences and paragraphs |
| Interface text | The body face, smaller than body text, a little heavier and brighter | A name in a list, a value in a panel |
| Muted text | The body face at the size of interface text, in grey | Facts beside the main line: a timestamp, a size, a path |
| Dim text | The body face at the size of interface text, in a darker grey | A line people can safely skip |
| Mono text | Monospace at the size of interface text | Values people read: durations, hashes, sizes |

Muted and dim text are the size of interface text, not of body text. They are for secondary lines in an interface, not for quieter paragraphs: there is no muted version of body text.

### mono values in a sentence

Mono text is monospace without the frame and the colour that <C slug="code" /> has. Use it for values people read, not for code.

### cut to one line

Text can be cut to a single line where its container ends.

### what the text is

What the text is can change while its look stays the same: text in any role can be a paragraph, or a heading at a level that <C slug="heading">the heading component</C> doesn't offer.

## behaviour

- Text is only there to be read: it takes no <Term id="focus">focus</Term> and handles no keys.
- A line cut to one line needs a width to cut against: it is at most as wide as its container.

The keyboard map, the element it renders and what it passes through are on the text's [React page](/design-system/react/?path=/docs/components-data-display-text--docs).

## accessibility

- **The meaning comes from what the text is, not from its look.** Make it a paragraph, a heading or a run of words inside other text, whichever it really is.
- **Colour carries no meaning.** Muted and dim text lower the emphasis, not the importance. Never put the only copy of something people need in dim text.
- Every text colour, dim included, has enough <Term id="contrast">contrast</Term> on every background.

Today: a line cut to one line is cut only for the eye. A <Term id="screen-reader">screen reader</Term> reads all of it, but people who see the screen, whether they use a keyboard, touch or a mouse, can't reach the rest: no tooltip is built in. Show the full value somewhere they can reach, in a detail view or in a <C slug="tooltip" />, whose trigger takes focus.

## content

- **Body text** is for full sentences. Follow the voice: sentence case, plain words, no exclamation marks.
- **Interface text** is a few words: a name, a value, a short phrase.
- **Muted text** states facts, not instructions: “Updated 3 min ago”, “412 GB used”.
- **Dim text** is only for what people can skip. Warnings and next steps never go there.
- **Mono text** is for values. A sentence set in mono to look technical is harder to read, not more precise.

## specs

| role | in code | typeface | weight | size / line height | colour |
| --- | --- | --- | --- | --- | --- |
| Body text | `variant="body"` (the default) | Inter (`--ff-ui`) | 400 | 16px / 1.55 | `--fg-2` |
| Interface text | `variant="ui"` | Inter | 500 | 13px / 1.4 | `--fg` |
| Muted text | `variant="muted"` | Inter | 400 | 13px / 1.4 | `--fg-muted` |
| Dim text | `variant="dim"` | Inter | 400 | 13px / 1.4 | `--fg-dim` |
| Mono text | `variant="code"` | JetBrains Mono (`--ff-mono`) | 500 | 13px / 1.5 | `--fg-2` |

- **Element:** a `span` with no margin. `as` picks another element and keeps the look: `as="p"` for a paragraph, `as="h3"` for a heading level `Heading` doesn't offer, `as="div"` for a block. `variant="code"` is still a `span`, not a `code` element.
- **Cut to one line:** `truncate`. An `inline-block` with `max-width: 100%`, on one line (`white-space: nowrap`), cut with `text-overflow: ellipsis`. It sets no `title`.
- **Contrast:** every text colour, `--fg-dim` included, meets 4.5:1 on every background.
- **The other components:** `Heading` renders a real `h1` or `h2`; `Code` renders a `code` element in a frame; `Field` renders the `label`, ties the hint and the error to the control and marks it invalid. `Text as="label"` is only styled text, tied to nothing.
