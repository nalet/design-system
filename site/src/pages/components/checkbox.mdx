# checkbox

A square box that turns one option on or off in a form that is saved later. It can also show a mixed state, for "some of these".

<Example label="a checkbox">
  <Playground />
</Example>

## when to use

- For an option that is part of a form people save or submit: `Include archived items`, `Notify the owner`.
- For a list of independent options where any number can be on.
- To select rows in a list or table, with a mixed box above them for "some selected" — see [selection and bulk actions](/design-system/patterns/selection-and-bulk-actions/).
- For one confirmation before a destructive step: `Also delete the snapshots`.

## when not to use

- **For a setting that applies the moment it changes.** Use a <C slug="switch" />. A checkbox reads as part of a form and sends people looking for a save button.
- **For one choice out of several that exclude each other.** Use a <C slug="select" />, or a native radio group for two or three — see [forms and settings](/design-system/patterns/forms-and-settings/).
- **To filter a list.** Use the <C slug="filter-bar" /> or <C slug="filter-tabs" />.
- **To start an action.** Use a <C slug="button" />; a checkbox only records a choice.

## anatomy

1. **Hit area** — the box, an 8px gap and the label text. A click anywhere on it toggles the box.
2. **Box** — 16 × 16px, square, 1px `--border-control` border on `--bg-2`. On or mixed: `--cloud-blue` fill and border.
3. **Mark** — a 12px check, or a dash when mixed, in `--bg`. It is hidden from assistive tech; the native state carries the meaning.
4. **Label** (optional) — Inter 13px in `--fg-2`.

## variants and states

| state | looks |
| --- | --- |
| Off | Empty box, `--border-control` border |
| On | `--cloud-blue` fill with a check |
| Mixed | `--cloud-blue` fill with a dash |
| Focused | 2px `--focus-ring` outline, 1px around the box; keyboard focus only |
| Disabled | Box and label at 50% opacity; cannot be focused, changed or submitted |

There is no hover style and no invalid look.

## behaviour

- A click on the label text toggles it too. A checkbox is one tab stop, and `space` toggles it.
- A mixed parent turns all its children on when it is pressed; the next press turns them all off.

The keyboard map and the attributes it sets are on its [React page](/design-system/react/?path=/docs/components-inputs-checkbox--docs).

## accessibility

- The real checkbox is on the page, so screen readers, the keyboard and form submission all use it. It reports on, off and mixed.
- Its label names the checkbox and makes its text part of the target.
- Without a visible label, give it an `aria-label` or `aria-labelledby` — nothing enforces it today, and an unnamed box is announced only as "checkbox". Name what it selects: `select api-7f9c`.
- The box is 16px. With a label the target is the whole label; unlabelled boxes in a list need at least 24px from one to the next, so each target stays separate.
- Today: there is no invalid state. Inside a <C slug="field" /> with an error, the error text shows, but the box does not change.
- Today: there are no forced-colours (Windows high contrast) styles.

## content

- Write the label as what is true when the box is on, and keep it positive: `Send a weekly summary`, not `Don't send a weekly summary`.
- Sentence case, short, no full stop: a checkbox label is in the body face, the reader's language. In a group, start the options the same way, so they read as answers to the legend.
- A mixed parent names the whole set: `All volumes`, `Back up all volumes`.
- The `aria-label` of a row's box names the row: `select worker-2`.
