## implementation notes

- It renders an inline-flex `<span>` and sets `data-state` on it.
- It takes no focus, has no keys of its own and doesn't animate.
- The glyph sits in an `aria-hidden` span, so screen readers skip it.
- `icon={false}` hides the glyph. `icon` also takes your own node in its place, and hides it from screen readers in the same way.
- For `warning` and `error`, a visually hidden `warning: ` or `error: ` goes in front of the text, so people who use a screen reader hear the state that the colour and the glyph show.
- `stateLabel` changes that word. A string replaces it, so `stateLabel="fehler"` reads “fehler: failed”. On a calm state, which has no word of its own, a string adds one. `false` leaves the word out.
- The text is lowercased with `text-transform`, so the DOM keeps the text as you wrote it.
- It isn't a live region, so a status that changes in place is not announced.
- `text` and `children` fill the same slot, and `text` wins when you pass both. `text` is what lets a vocabulary entry spread in.
- Every other `<span>` attribute (`id`, `title`, `aria-*`, `data-*`) and the `ref` reach the outer `span`.
- axe-core finds no violations in any state, as a chip or as text, colour contrast included.

### vocabulary: `defineStates`

Write one table for each object, with every value, its state and its words.

```tsx
import { ObjectStatus, defineStates } from '@nalet/design-system';

type LinkValue = 'open' | 'firewalled' | 'checking' | 'down' | 'unknown';

const LINK = defineStates<LinkValue>({
  open: { state: 'success', text: 'open' },
  firewalled: { state: 'warning', text: 'connection firewalled' },
  checking: { state: 'information', text: 'checking' },
  down: { state: 'error', text: 'unreachable' },
  unknown: { state: 'neutral', text: 'not checked yet' },
});

<ObjectStatus {...LINK[row.link]} />
```

`defineStates` returns a frozen copy of the table. When you pass your value type as the type argument, as above, TypeScript makes the table exhaustive: a value without a row, or a row for a value that doesn't exist, is a type error. Without the type argument, the keys you write are the type. Writing the table once also means a reviewer reads in one place that `firewalled` is a warning, not a success.

### sorting: `STATE_SEVERITY`

`STATE_SEVERITY` ranks the states so you can sort a list by status, most urgent first: `error` 4, `warning` 3, `information` 2, `neutral` 1, `success` 0.

```tsx
rows.sort((a, b) => STATE_SEVERITY[HOST[b.status].state] - STATE_SEVERITY[HOST[a.status].state]);
```

`OBJECT_STATES` lists the five states from `neutral` to `error`. Use it for a legend or a filter.

## props

| export | what it is |
| --- | --- |
| `defineStates(table)` | Returns a frozen copy of the table, which maps each domain value to `{ state, text }` (a `StateSpec`). |
| `STATE_SEVERITY` | The frozen ranking: `error` 4, `warning` 3, `information` 2, `neutral` 1, `success` 0. |
| `OBJECT_STATES` | The five states as an array, with `neutral` first. |
| `ObjectState`, `StateSpec` | The types of a state and of a vocabulary entry. |
