## implementation notes

- renders a native `<textarea>` — the box is the element itself — so the browser provides the keyboard model.
- the component holds no state. use `defaultValue`, or `value` with `onChange`.
- a [field](?path=/docs/components-inputs-field--docs) renders a `<label for>` and links the hint or error with `aria-describedby`.
- `invalid` sets `aria-invalid="true"` and the `--state-error` border. a field's `error` sets `invalid` for you. read-only is the native `readOnly`.
- the limit is the native `maxLength`. link a count to the textarea with `aria-describedby`, as the controlled example does.
- every native `<textarea>` attribute passes through (`value`, `onChange`, `maxLength`, `name`, `aria-*`, …), and the ref reaches the `<textarea>`.

| key | does |
| --- | --- |
| `tab` / `shift+tab` | moves focus to / from the field. `tab` does not type a tab character. |
| `enter` | starts a new line. it never submits the form. |
| arrows, `home`, `end` | move the caret; with `shift` they select. |
