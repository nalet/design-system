## implementation notes

- It is a native checkbox with `role="switch"`. A `<label>` wraps the track and the label text.
- The native `<input type="checkbox" role="switch">` lies over the track, transparent. It takes the focus, the clicks and the form value, and the browser gives it the keyboard behaviour.
- `role="switch"` is what makes screen readers announce a switch.
- The state is the native `checked`, so don't add `aria-checked`.
- The component holds no state of its own. Use `defaultChecked`, or `checked` with `onChange`.
- Apply the setting in `onChange`, because a switch takes effect at once.
- Focus is drawn on `:focus-visible`, so it shows when someone uses the keyboard.
- `enter` doesn't toggle it, just as it doesn't toggle any native checkbox.
- `className` lands on the outer `<label>`. Every other attribute (`checked`, `defaultChecked`, `onChange`, `name`, `aria-*`) and the ref land on the native `<input type="checkbox" role="switch">`.
- Today: inside a [field](?path=/docs/components-inputs-field--docs) with an `error`, React warns about an unknown `invalid` attribute.

| key | does |
| --- | --- |
| `tab` / `shift+tab` | Moves focus to / from the switch. |
| `space` | Toggles it. |
