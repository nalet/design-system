## implementation notes

- `Toolbar` renders a `<div role="toolbar">`, named by `label` (`aria-label`). it carries `tabindex="-1"` so it can hold focus itself: when the control that has focus goes away, the toolbar takes focus instead of the page.
- the emphasized action is a `sm` `Button` with `variant="primary"`, or `"danger"` when it is also `danger`; the others are `sm` `Button`s, `default` or `danger`. an action's `icon` goes in the button's `leading` slot.
- a second `emphasized` action renders as a default button, and the toolbar warns in the console: `Toolbar "missing episodes": 2 emphasized actions; only the first is emphasized.`
- the overflow is an `ActionMenu` named by `overflowLabel` (default "more actions"). `overflow: true` keeps an action in it. in the menu, a `disabled` or `loading` action is a disabled item, and a `danger` action a danger item.
- the toolbar measures its own width, inside its padding, with a `ResizeObserver`: below `collapseBelow`, 560px by default, every action but the emphasized one moves into the menu. until it has been measured, and wherever there is no `ResizeObserver`, it lays out as wide.
- one tab stop is a roving tabindex: after every render, the toolbar puts `tabindex="0"` on one control and `-1` on the others, so there is still one tab stop when actions come and go.
- the arrows move through every enabled button, link, input and select inside the toolbar, in order — including the heading's and your `children`'s. disabled buttons are skipped, and so is a `loading` one, which is disabled while it is busy.
- in an `input` or a `select`, the arrow keys, `home` and `end` stay with the field; `tab` leaves the toolbar from there.
- an `onKeyDown` you pass runs first. call `preventDefault()` on a key to keep the toolbar from acting on it.
- `SelectionToolbar` takes `selectedCount`. at 0 it shows `heading` and no emphasized action, unless `primaryAction(0)` returns one. above 0 it shows the count (`formatSelected`, by default `8 selected` with thousands separators), `clear` when you pass `onClearSelection` (`clearLabel` renames it), `selectAll` when you pass it, and the emphasized action that `primaryAction(n)` returns; return `null` for none. `actions` are never emphasized. build the bulk action's label from `n` in `primaryAction`.
- a visually hidden `aria-live="polite"` region in the heading announces every change of `selectedCount` after the first render: the count as `formatSelected` writes it, or `selection cleared` at 0.
- `Toolbar` passes other `<div>` attributes (all but `title`) and its `ref` to the `role="toolbar"` element. `SelectionToolbar` takes everything `Toolbar` takes except `heading` and `actions`, which it defines itself, and passes the rest on.
- axe-core finds no violations in either toolbar.
- today: a `textarea` in `children` is not in the arrow-key set.

| key | does |
| --- | --- |
| `tab` / `shift+tab` | moves into the toolbar, onto one control — the first, or the one last focused in it — and out of it on the next press. |
| `→` / `←` | moves to the next / previous control, wrapping at the ends. |
| `home` / `end` | moves to the first / last control. |
| `enter` / `space` | native: activates the focused button. |
| `↓` / `↑` on `more actions` | opens the overflow menu. inside it, the [action menu](?path=/docs/components-actions-action-menu--docs)'s keys apply. |

## props

<ArgTypes of={ToolbarStories} />

each entry in `actions`:

| field | does |
| --- | --- |
| `id` | a key, unique within the toolbar |
| `label` | the button's text: a verb and its object |
| `onSelect` | runs on press, or when chosen from the overflow menu |
| `emphasized` | the one primary action; at most one |
| `danger` | a danger button, or a danger item in the menu |
| `disabled`, `loading` | as on a button; in the menu, either makes a disabled item |
| `overflow` | always in the `more actions` menu |
| `icon` | decoration before the label |
