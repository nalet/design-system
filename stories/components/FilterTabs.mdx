# filter tabs

key figures that filter one list: each tab is a count over a label — `3` over `needs attention` — and choosing a tab filters the list below it. a tablist with one tab stop, where the arrow keys select as they move.

<Canvas of={FilterTabsStories.Playground} />

## when to use

- at the top of one list, to show the few subsets people act on and let them pick one: `missing`, `on their way`, `needs attention`.
- when each subset's count is worth seeing before choosing it.
- for one subset at a time, from two to about six. the [worklist](?path=/docs/patterns-worklist--docs) puts them over its table.

## when not to use

- **to switch between views of one object** — overview, logs, metrics. use [tabs](?path=/docs/components-navigation-tabs--docs).
- **for filters people combine** — a kind, and a time, and a state. use the facets of a [filter bar](?path=/docs/components-inputs-filter-bar--docs), which combine.
- **for a figure that filters nothing.** show the number as text, or as a [badge](?path=/docs/components-data-display-badge--docs) beside what it counts.
- **to go to another page.** use a link.

## anatomy

1. **tablist** — a flex row with a 1px `--border` rule under it. when the tabs don't fit, the row scrolls sideways, and the edge where more tabs are cut off fades out over 48px.
2. **tab** — a `<button>` with `role="tab"`: at least 96px wide, 8px 16px 12px padding, jetbrains mono, left-aligned. the count sits on top, but the label comes first in the dom, so it is read first: "needs attention 3".
3. **count** (optional) — 20px, weight 600, tabular figures, with thousands separators (`2,500`), in `--fg` or in the colour of the tab's `state`.
4. **label** — 12px, weight 500, lowercase, one line, in `--fg-muted`; `--fg` on hover and when selected.
5. **selection** — a 2px `--cloud-blue` underline, laid over the row's rule.
6. **panel** — yours: the list the tabs filter. it isn't part of the component; how to wire it is under accessibility.

## variants and states

| state | looks |
| --- | --- |
| rest | label in `--fg-muted`; count in `--fg` or in its state's colour |
| hover | `--surface` fill, label in `--fg` |
| selected | label in `--fg`, 2px `--cloud-blue` underline |
| focus | a 2px `--focus-ring` outline inside the tab |
| disabled | 45% opacity. it can't be focused, chosen or reached with the arrow keys |

### states on counts

`state` colours the count, and only the count, when the number carries a meaning: `error` for `needs attention`, `warning` for `can't be checked`, `information` for `on their way` (the colours of the [status vocabulary](?path=/docs/patterns-status-vocabulary--docs)). leave it off for counts that only say how many, `missing` or `not yet aired`: they stay plain `--fg`. a tab without a `count` shows no state at all. the example at the top uses both.

## behaviour and keyboard

| key | does |
| --- | --- |
| `tab` | moves focus into the row, onto the selected tab — the only one with `tabindex="0"` — and out of the row on the next press. |
| `→` / `←` | selects the next / previous enabled tab, wrapping at the ends: calls `onChange` and moves focus to it. |
| `home` / `end` | selects and focuses the first / last enabled tab. |
| `enter` / `space` | native button: selects the focused tab. |

- automatic activation: the selection follows focus, so every arrow press calls `onChange` and filters the list. keep the filtering quick — it is usually local — or let a slow list settle before it loads.
- a click selects a tab.
- controlled only: pass `value` and set it in `onChange`. a `value` you don't update freezes the row.

## accessibility

- the row is a `tablist` named by `label` (required): what it filters, and by what — `filter missing by state`. each tab is a `<button>` with `role="tab"` and `aria-selected`; only the selected tab is in the tab order.
- a tab's name is its label, then its count: "needs attention 3". a real space sits between the two in the dom, so they are never read as one word.
- **wiring the panel.** pass `panelId`, and every tab points at your panel with `aria-controls`. pass `idPrefix`, and each tab's id is `filterTabId(idPrefix, tab.id)`. render the list inside the panel, named by the selected tab:

```tsx
import { FilterTabs, filterTabId } from '@nalet/design-system';

<FilterTabs
  label="filter missing by state"
  tabs={tabs}
  value={tab}
  onChange={setTab}
  panelId="missing-panel"
  idPrefix="missing-tabs"
/>
<div id="missing-panel" role="tabpanel" aria-labelledby={filterTabId('missing-tabs', tab)}>
  {/* the list */}
</div>
```

the panel is then named after the selected tab: "needs attention 3". without `idPrefix` the tabs still get ids, but from a generated prefix you can't know, so pass it whenever you render the panel, and keep it unique on the page. the [worklist](?path=/docs/patterns-worklist--docs) does all of this for you.

- the state colour on a count is a second signal: the label says what the count means. a count has no glyph, unlike an [object status](?path=/docs/components-feedback-status-object-status--docs), so never let the colour say what the label doesn't.
- a count that changes is not announced.
- axe-core finds no violations, with the panel wired.

today:

- a `value` that matches no enabled tab leaves the row without a tab stop: no tab has `tabindex="0"`, or the one that has it is disabled, so `tab` can't reach the row.
- disabled tabs can't be focused, so screen-reader users don't learn that they exist.

## content

- **label** — what the tab keeps, in the list's words: `needs attention`, `on their way`, `can't be checked`. a few words, lowercase.
- **count** — exact, never rounded. leave it out when it isn't known, rather than showing `0`.
- **first tab** — the whole list, `missing` or `all`, so there is always a way back.
- **the tablist's `label`** — what it filters, and by what: `filter missing by state`.

## props

`FilterTabs` passes other `<div>` attributes (all but `onChange`, which is its own) and its `ref` to the wrapper around the tablist; `label` names the tablist itself.

<ArgTypes of={FilterTabsStories} />

each entry in `tabs` has an `id`, a `label`, and optionally a `count`, a `state` and `disabled`. `filterTabId(idPrefix, tabId)` returns a tab's id, for the panel's `aria-labelledby`.
