# message handling

say each thing once, in the one place that fits what it is about and how long it is true.

<Example label="the four places a message goes" column>
  <MessageStrip state="warning" live="off" details="the catalog holds a title of this name without an identity (item 3f2a9c1e-5b7d-4c11-9e02-6a1d0b8f4c21)">105 titles can&apos;t be checked: the catalog holds them without an identity.</MessageStrip>
  <div style={{ display: 'flex', gap: 'var(--s-3)', alignItems: 'center', flexWrap: 'wrap' }}>
    <ObjectStatus state="error">needs attention</ObjectStatus>
    <Button size="sm" variant="primary" onClick={() => toast('8 episodes queued', { state: 'success' })}>grab 8 selected</Button>
  </div>
  <Field label="storage floor (gb)" error="must be a number">
    <Input defaultValue="fifty" />
  </Field>
  <Toaster />
</Example>

## which one

| the message is about | it lasts | use | for example |
| --- | --- | --- | --- |
| a condition of the page's content | until the condition changes | **message strip** — information, warning or error | `105 titles can't be checked: the catalog holds them without an identity.` |
| a load that failed, with older content still on screen | until it works again | **message strip, warning**: say how old the content is, offer "try again", raw error under details | `couldn't refresh the list; it shows what was loaded 4m ago.` |
| a load that failed, with nothing to show | until it works again | **illustrated message, error** in place of the list, with "try again" — see [empty states](?path=/docs/patterns-empty-states--docs) | `couldn't load the list` · `try again` |
| an action the person just took, that worked | a few seconds | **toast** — never focused, no actions | `8 episodes queued · 2 skipped: held already or under way` |
| an action that failed | until dismissed or retried | **message strip, error**, dismissible, raw error under details | `couldn't queue the grab.` |
| one item's state | as long as the item has it | **object status** / **status cell** | `needs attention` · `the release was removed by its source` |
| one field's value | until it is fixed | **field error** | `must be a number` |
| technical detail behind any of these | on request | the strip's **details** disclosure, or a row's `<details>` | `item 3f2a9c1e-…`, `http 502 bad gateway` |
| a decision before going on | until answered | **modal** — for the decision, not for the message | `delete volume` |

## rules

- **one place per message.** an error is a strip *or* a toast, never both; a row's status is not repeated in a strip.
- **at most one or two strips** on a screen. a third means the screen has a problem to fix, not a message to add.
- **toasts are for success and progress.** never for an error a person must act on — it would leave before they read it — and never with an action in it.
- **errors say what failed and offer the way forward**: `couldn't load the list.` + `try again`. the raw error goes under details.
- **keep what is known.** when a refresh fails, keep showing the last data and say how old it is, as a warning.
- **no ids, codes or raw errors in primary text.** they go behind details.

## behaviour

- a strip stays until its condition changes. the strip doesn't remember a dismissal — the screen does: bring a dismissed strip back when its condition changes again (a new count, a new failure).
- a toast leaves after five seconds, pauses while hovered, and at most three are shown.
- error strips are `role=alert`, so a failure is announced when it appears; other strips are `role=status`.
- focus never moves to a message. after a failed form save, focus moves to the first invalid field instead — see [forms and settings](?path=/docs/patterns-forms-and-settings--docs).

## content

- a strip: one or two sentences — what is true, and what it means for this screen. actions are verbs: `show them`, `ask the catalog again`, `try again`.
- a toast: what happened, in counts: `8 episodes queued`. no "successfully", no full stop needed.
- an error: `couldn't …` + the object, then the way forward. no blame, no "oops".

## do and don't

<DoDont>
  <Do caption="a failed action: an error strip with the raw text one click away." column>
    <MessageStrip state="error" live="off" details="POST /api/targets/grab: http 503 service unavailable" onDismiss={() => undefined}>couldn&apos;t queue the grab.</MessageStrip>
  </Do>
  <Dont caption="an error in a toast: gone before it is read, nothing to act on.">
    <Button onClick={() => toast('error 503: service unavailable', { state: 'error' })}>show it</Button>
  </Dont>
</DoDont>

<DoDont>
  <Do caption="a toast for the result of an action, in counts.">
    <Button size="sm" variant="primary" onClick={() => toast('8 episodes queued', { state: 'success' })}>grab 8 selected</Button>
  </Do>
  <Dont caption="a strip that stays forever for something that happened once." column>
    <MessageStrip state="success" live="off">success! your grab request was submitted successfully.</MessageStrip>
  </Dont>
</DoDont>
