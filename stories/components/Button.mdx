## implementation notes

- It renders a native `<button>`, so the browser gives it the keyboard behaviour for free.
- `type` defaults to `"button"`, not the browser's `"submit"`, so a button inside a form doesn't send it by accident. Pass `type="submit"` for the button that submits a form.
- `loading` shows a spinner in the leading slot, disables the button and sets `aria-busy="true"`.
- The spinner is a `status` named “loading”.
- While it is loading, the button keeps its width, so nothing around it jumps.
- `disabled` dims the button to 45% and takes it out of the tab order.
- A disabled or loading button ignores clicks and can't be focused.
- `leading` and `trailing` take an element, such as `<Icon icon={Rocket} />`.
- `trailing` is hidden while the button is `loading`.
- The label is lowercased with `text-transform`, but the DOM keeps the text you wrote, so write it the way a screen reader should read it.
- A focused button shows a 2px `--focus-ring` outline on `:focus-visible`, so the ring shows for keyboard focus and not for a click.
- Every native `<button>` attribute passes through, such as `onClick`, `type` and `aria-*`, and the `ref` reaches the `<button>`.

| key | does |
| --- | --- |
| `tab` / `shift+tab` | Moves focus to / from the button. |
| `enter` / `space` | Activates it. |
