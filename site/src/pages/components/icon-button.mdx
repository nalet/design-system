# icon button

A square action that shows only an icon. It has the variants and sizes of <C slug="button" />; `label` is required and becomes its accessible name.

<Example label="the four variants">
  <Variants />
</Example>

## when to use

- In dense places where a text label does not fit: a toolbar, a card or panel header, a table row (one or two actions there; more go into an <C slug="action-menu" />).
- For actions people recognise from the icon alone: copy, refresh, close, delete.
- Next to a field or a title, for a small action on it: copy a value, open a log.

## when not to use

- **When there is room for a label, or it is the main action of the screen.** Use a <C slug="button" /> with a label, and the icon before it if it helps. A word is read faster than an icon is decoded.
- **For an on/off setting.** Use a <C slug="switch" />. The icon button has no pressed look.
- **For more than three or four actions side by side.** Put them in a <C slug="toolbar">toolbar</C> and let the rest overflow into an <C slug="action-menu" />.
- **For several actions on every row of a table.** Use one action menu per row and a selection toolbar for bulk actions — see [selection and bulk actions](/design-system/patterns/selection-and-bulk-actions/).
- **To go somewhere.** Navigation is a link, not a button. A button that changes the address breaks open-in-new-tab and the browser's back.

## anatomy

1. **Container** — square, a 1px border, 28, 34 or 42px on each side by size. The icon sits in the centre.
2. **Icon** — 16px at `md`, 12px at `sm` and 20px at `lg`, as in the sizes example. While the button is busy, a spinner takes its place: 12px at `sm`, 14px otherwise.
3. **Label** — not drawn. It is the button's accessible name, and the browser shows it as its own tooltip.

## variants and states

The four variants of button. Only `primary` is filled.

| variant | looks | use for |
| --- | --- | --- |
| `primary` | `--cloud-blue` fill, dark icon, lighter blue on hover | The one emphasized action of a toolbar or panel |
| `default` | `--surface` fill, `--border-2` hairline; `--surface-2` and a `--cloud-blue` border on hover | A standalone icon action |
| `ghost` | No fill or border until hover; icon in `--fg-2`, `--fg` on hover | Rows of actions in a toolbar or a table row |
| `danger` | `--signal-amber` outline and icon, amber fill on hover | An action that deletes or cannot be undone |

Three sizes: `sm` (28px) for table rows and dense toolbars, `md` (34px, the default), `lg` (42px) beside a large input or button. Match the height of the controls next to it.

## behaviour

- An icon button acts on the current screen when it is pressed, with a pointer, `enter` or `space`.
- A busy or disabled icon button ignores presses.
- On mouse hover the browser shows the label as its own tooltip, after a delay. It never shows on keyboard focus or touch.

The keyboard map and the attributes it sets are on its [React page](/design-system/react/?path=/docs/components-actions-icon-button--docs).

## accessibility

- `label` is required, and it is the whole accessible name. Write it as you want it read.
- The same words are the browser's own tooltip. Assistive tech may read them a second time, as the description, and the tooltip is unstyled and appears only on mouse hover.
- Sighted keyboard and touch users never see the label. Use icons whose meaning is not in doubt, or a <C slug="button" /> with a visible label.
- The icon is decoration, hidden from assistive tech: the label names the action.
- A screen reader may not announce that the button is busy. When the outcome matters, announce it elsewhere, with a <C slug="toast" /> for instance.
- The focus ring is the 2px `--focus-ring` outline every control shares — see [interaction](/design-system/foundations/interaction/#focus).
- Today: a busy icon button is disabled, and a focused button that becomes disabled can lose focus. Keyboard and screen-reader users who pressed it can be moved off it while it loads.
- Today: there is no pressed state. Use a <C slug="switch" /> for on/off.
- Today: don't wrap it in a <C slug="tooltip" />. The tooltip's wrapper is a tab stop of its own, so the pair takes two tab stops, the description lands on the wrapper instead of the button, and the browser's own tooltip still appears.

## content

- `label` is an action, verb first, lowercase: `restart worker`, `copy link`, `delete volume`. Never the icon's name (`arrow`, `trash`).
- When the button repeats on every row or card, name the object: `delete api-7f9c`, not `delete`. Otherwise a screen reader's list of buttons is a column of identical names.
- One icon, one meaning, everywhere. An icon that stands for two actions can no longer be read as either.
