# checkbox

a square box that turns one option on or off in a form that is saved later. it can also show a mixed state, for "some of these".

<Canvas of={CheckboxStories.Playground} />

## when to use

- for an option that is part of a form people save or submit: `include archived items`, `notify the owner`.
- for a list of independent options where any number can be on.
- to select rows in a list or table, with a mixed box above them for "some selected" — see [selection and bulk actions](?path=/docs/patterns-selection-and-bulk-actions--docs).
- for one confirmation before a destructive step: `also delete the snapshots`.

## when not to use

- **for a setting that applies the moment it changes.** use a [switch](?path=/docs/components-inputs-switch--docs). a checkbox reads as part of a form and sends people looking for a save button.
- **for one choice out of several that exclude each other.** use a [select](?path=/docs/components-inputs-select--docs), or a native radio group for two or three — see [forms and settings](?path=/docs/patterns-forms-and-settings--docs).
- **to filter a list.** use the [filter bar](?path=/docs/components-inputs-filter-bar--docs) or [filter tabs](?path=/docs/components-navigation-filter-tabs--docs).
- **to start an action.** use a [button](?path=/docs/components-actions-button--docs); a checkbox only records a choice.

## anatomy

1. **hit area** — the whole `<label>`: the box, an 8px gap and the label text. a click anywhere on it toggles the box.
2. **box** — 16 × 16px, square, 1px `--border-control` border on `--bg-2`. on or mixed: `--cloud-blue` fill and border.
3. **mark** — a 12px check, or a dash when mixed, in `--bg`. it is hidden from assistive tech; the native state carries the meaning.
4. **label** (optional) — inter 13px in `--fg-2`.

the native `<input type="checkbox">` lies over the box, transparent. it takes the focus, the clicks and the form value.

## variants and states

| state | looks | set by |
| --- | --- | --- |
| off | empty box, `--border-control` border | — |
| on | `--cloud-blue` fill with a check | `checked` or `defaultChecked` |
| mixed | `--cloud-blue` fill with a dash | `indeterminate` |
| focused | 2px `--focus-ring` outline, 1px around the box; keyboard focus only | native `:focus-visible` |
| disabled | box and label at 50% opacity; cannot be focused, changed or submitted | `disabled` |

there is no hover style and no invalid look.

## behaviour and keyboard

the control is a native checkbox, so the browser provides the keyboard model.

| key | does |
| --- | --- |
| `tab` / `shift+tab` | moves focus to / from the checkbox. |
| `space` | toggles it. on a mixed box this also clears the mixed state. |

- `enter` does not toggle a checkbox.
- a click on the label text toggles it too.
- the component holds no state. use `defaultChecked`, or `checked` with `onChange`.
- the browser clears the mixed state on every click, and the component re-applies `indeterminate` only when the prop changes. recompute it in `onChange`, as the parent example above does.

## accessibility

- the real checkbox is on the page, so screen readers, the keyboard and form submission all use it. it reports on, off and mixed (`aria-checked="mixed"` comes from the native `indeterminate`).
- with `label`, the wrapping `<label>` names the checkbox and makes its text part of the target.
- without `label`, pass `aria-label` or `aria-labelledby` — nothing enforces it today, and an unnamed box is announced only as "checkbox". name what it selects: `select api-7f9c`.
- the box is 16px. with a label the target is the whole label; unlabelled boxes in a list need at least 24px from one to the next, so each target stays separate.
- today: if `indeterminate` stays `true` across a click, the dash stays drawn but the browser's mixed state is gone, so assistive tech announces on or off while the screen shows mixed.
- today: there is no invalid state. inside a [field](?path=/docs/components-inputs-field--docs) with `error`, the error text shows and `aria-invalid` is set, but the box does not change, and react warns about an unknown `invalid` attribute.
- today: there are no forced-colours (windows high contrast) styles.

## content

- write the label as what is true when the box is on, and keep it positive: `send a weekly summary`, not `don't send a weekly summary`.
- lowercase, short, no full stop. in a group, start the options the same way, so they read as answers to the legend.
- a mixed parent names the whole set: `all volumes`, `back up all volumes`.
- the `aria-label` of a row's box names the row: `select worker-2`.

## props

`className` lands on the outer `<label>`; every other attribute — `checked`, `defaultChecked`, `onChange`, `name`, `value`, `aria-*` — and the ref land on the native `<input type="checkbox">`.
