## implementation notes

- The trigger is a ghost `IconButton` showing three squares. `icon` replaces them with an icon of your own.
- With `buttonLabel`, the trigger is a default `Button` with your text and a chevron after it.
- `size` and `className` go to the trigger. `size` is `sm` by default, or `md`.
- The trigger has `aria-haspopup="menu"` and `aria-expanded`, so a screen reader announces a button that opens a menu, and whether the menu is open. While it is open, `aria-controls` points at it.
- The menu exists only while it is open.
- It renders into `document.body` (a portal), with `position: fixed` and `z-index: 150`. That puts it outside any ancestor with `overflow: hidden`, so no table cell, scroll container or panel can cut it off.
- The menu has `role="menu"` and `tabindex="-1"`, and takes its name from the trigger through `aria-labelledby`.
- Each item is a `<button type="button">` with `role="menuitem"` and `tabindex="-1"`. `tab` doesn't stop on the items, because inside the menu the arrow keys move between them.
- A disabled item gets `aria-disabled="true"`, not the native `disabled`, so it stays in the menu, where people can still see it.
- An item's icon sits in a span with `aria-hidden="true"`, so a screen reader reads only the label.
- The menu is measured before it shows: it stays `visibility: hidden` until it is placed, so it never flashes in the wrong place.
- `align` lines up the menu's `end` edge with the trigger's (the default), or its `start` edge.
- While it is open, the menu listens for `pointerdown` on the document, so a press outside closes it.
- It also listens for `scroll` and `resize` on the window, so it follows the trigger. It catches `scroll` in the capture phase, so scrolling any container counts.
- When the menu opens, focus goes to the first item that isn't disabled, or to the last one when `↑` opened it. When every item is disabled, focus goes to the menu itself.
- `onOpenChange(open)` is called each time the menu opens or closes.
- `loading` puts a spinner in the trigger, sets `aria-busy` and keeps the menu from opening.
- `disabled` turns the whole menu off. Both `loading` and `disabled` disable the trigger, so it can't take focus.
- With `buttonLabel`, the visible text is the name and `label` isn't used, so what people see is what speech-input users say. The type still requires `label`, so pass the same words.
- `ActionMenu` passes no other attributes through.
- axe-core finds no violations, with the menu closed or open.

| key | does |
| --- | --- |
| `enter` / `space` on the trigger | Opens the menu and focuses its first item that isn't disabled. |
| `↓` on the trigger | Also opens the menu on its first item. |
| `↑` on the trigger | Opens the menu on its last item. |
| `↓` / `↑` in the menu | Moves to the next / previous item, wrapping at the ends. Disabled items are skipped. |
| `home` / `end` | Moves to the first / last item. |
| `enter` / `space` on an item | Closes the menu, puts focus back on the trigger, then runs the item. |
| `esc` | Closes the menu and puts focus back on the trigger. The key goes no further, so a modal around the menu stays open. |
| `tab` / `shift+tab` | Closes the menu, and focus moves on from the trigger as if the menu had not been there. |

## props

<ArgTypes of={ActionMenuStories} />

Each entry in `items` has these fields:

| field | does |
| --- | --- |
| `id` | A key, unique within the menu |
| `label` | The item's text: a verb and its object |
| `onSelect` | Runs once the menu has closed and focus is back on the trigger, so a modal it opens returns focus there when it closes |
| `disabled` | Stays in the menu, can't be run, and the arrow keys skip it |
| `danger` | Shows the label in `--signal-amber`, for an item that deletes something or can't be undone |
| `icon` | Decoration before the label |
