# colour

Colour on our screens always means something. The <Term id="canvas">canvas</Term> is dark, text comes in four steps of grey, there is one blue for actions, and there are five colours for states. Colour says what something *is*. It never decorates, and it never says anything on its own.

## the palette

Every colour is a <Term id="token">design token</Term>: a named value, stored once. The components use the name, never the colour's code, so a colour can change in one place and every screen follows. The swatches above are drawn from the same tokens, so they can't drift apart from the components.

| group | what it is for |
| --- | --- |
| Canvas | The page, recessed areas, panels, hover, a selected row, and the thin lines between things |
| Text | Four greys: titles and values, body text, labels and details, and hints, from the strongest to the faintest |
| Brand | The blue of the chevron, of links and of the emphasized action; a cyan for the cursor and the active stroke |
| Signal | The raw green, amber and red. The components don't use them for status; they use the states below |
| Controls | The edge that makes a control visible, and the keyboard focus outline |
| States | The colour of a status, a message or a toast: one of five meanings |

## semantic state

Statuses, messages and highlights take their colour from a <Term id="semantic-state">state</Term>, never from the name of a colour. Each state has a colour for its text and symbol, a faint <Term id="tint">tint</Term> and a border. Every component that shows a state also gives it a symbol of its own shape, so the state never rests on colour alone.

| state | means | for example | never for |
| --- | --- | --- | --- |
| <Status state="neutral">neutral</Status> | A plain fact, with no judgement | “missing”, “queued”, “not searched yet” | Something that needs attention |
| <Status state="information">information</Status> | Under way, or worth knowing; nothing to fix | “on its way”, “syncing”, “asking again” | Decoration, or “this is blue” |
| <Status state="success">success</Status> | Done, and good | “held”, “saved”, “healthy” | Anything with a problem in it, however small |
| <Status state="warning">warning</Status> | It works, but not fully; someone should look | “connection firewalled”, “degraded”, “can't be checked” | A failure (that is an error), or emphasis |
| <Status state="error">error</Status> | Failed or blocked; it needs action | “needs attention”, “unreachable”, “couldn't load” | An *action* that destroys something (that is the danger button) |

The words decide the state, not the other way round. Write the status in the object's own words first, then ask which of the five meanings it has. A domain's whole vocabulary lives in one table; [status vocabulary](/design-system/patterns/status-vocabulary/) shows how.

## using colour

- **Text has four weights.** The brightest grey for titles and values, the next for body text, a muted grey for labels and details, and a dim grey for hints and the least important line. To make something quieter, make it shorter rather than dimmer.
- **On a tinted background, use the muted grey or brighter.** The dim grey isn't clear enough on two of the tints.
- **Blue is the action colour.** It marks the chevron, links, the emphasized button, the selected tab and the bar of a selected row. Information uses the same blue, so make information read as information, with words and a symbol, and not as a link.
- **Status goes through a component.** The <C slug="status" />, the <C slug="banner" />, the <C slug="toast" />, the filter tabs' counts and the data table's highlighted rows take a state, never a colour. The <C slug="badge" /> still has colour tones: use it for labels and counts, not for status.
- **Never colour alone.** A state also has a symbol and words, a selected row also has a ticked checkbox, and a field with an error also shows the error in words.

## contrast

Text has to stand out enough from what is behind it to be read, by everyone, including people with low vision. That difference is the <Term id="contrast">contrast ratio</Term>. ## themes

The system is dark only, and it tells the browser so, which makes the browser's own controls, scrollbars and form fields dark too. A light theme and a high-contrast theme are planned, but they aren't here yet: there is no theme switch, and nothing follows a person's light or dark preference, or <Term id="forced-colours">forced colours</Term>, today. When forced colours are on, the browser's colours replace the palette.

## specs

| group | tokens |
| --- | --- |
| Canvas | `--bg`, `--bg-2`, `--surface`, `--surface-2`, `--surface-selected`, `--border`, `--border-2` |
| Foreground | `--fg` (titles and values), `--fg-2` (body text), `--fg-muted` (labels and meta), `--fg-dim` (hints and helpers) |
| Brand | `--cloud-blue` (the `>` chevron, links, the primary action), `--cloud-cyan` (the cursor, the active stroke) |
| Signal | `--signal-green`, `--signal-amber`, `--signal-red` |
| Controls | `--border-control` (a control's boundary, 3:1), `--focus-ring` (the keyboard focus outline) |
| Semantic state | `--state-*`, `--state-*-bg`, `--state-*-border` for `neutral`, `information`, `success`, `warning` and `error` |

- **Source.** Every colour is a token in `tokens/tokens.json`. Components read the CSS custom properties (`var(--fg-2)`), never a hex value. The swatches are painted with the custom properties and labelled from the typed tokens, both generated from that file.
- **On a tint.** Use `--fg-muted` or brighter. `--fg-dim` is outside the policy there: 4.32:1 on `--state-warning-bg` and 4.42:1 on `--state-information-bg`.
- **Blue.** `--cloud-blue` marks the chevron, links, the primary button, the selected tab and a selected row's rule.
- **Status.** The status, the banner, the toast, the filter tabs' counts and the data table's `rowHighlight` take a `state`; the badge takes a `tone`.
- **Contrast.** Computed by `tokens/contrast.mjs`, the same function the token test runs (`tokens/contrast.test.ts`, part of `npm test` and of CI) and the token build warns with.
- **Themes.** The tokens declare `color-scheme: dark`. Nothing responds to `prefers-color-scheme` or `forced-colors` today.
