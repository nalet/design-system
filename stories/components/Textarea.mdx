# textarea

a square, multi-line text field in mono type that people can drag taller. put it in a [field](?path=/docs/components-inputs-field--docs) for its label, hint and error.

<Canvas of={TextareaStories.Playground} />

## when to use

- for text that runs past one line: a description, release notes, a comment, a config someone pastes in.
- inside a [field](?path=/docs/components-inputs-field--docs), which labels it and wires its hint and error.

## when not to use

- **for one line.** use an [input](?path=/docs/components-inputs-input--docs). a name, a host or a number does not need the room, and `enter` in a textarea adds a line instead of submitting.
- **to show text that people only read or copy**, such as a log or a generated config. use [code](?path=/docs/components-data-display-code--docs) as a block; an editable box suggests the text can be changed.
- **to pick from known values.** use a [select](?path=/docs/components-inputs-select--docs).
- **to lay out a whole form.** start from [forms and settings](https://nalet.github.io/design-system/patterns/forms-and-settings/).

## anatomy

1. **box** — the native `<textarea>` itself: square, 1px `--border-control` border on `--bg-2`, 12px padding, the full width of its container.
2. **text** — jetbrains mono 13px, line height 1.5, in `--fg`. the placeholder is `--fg-dim`.
3. **resize handle** — the browser's own, in the bottom-right corner. it drags vertically only.

## variants and states

one size. the height comes from `rows` — 4 by default — and people can drag it taller. set `rows` to the length you expect: 2 for a short note, 8 for a pasted config.

<Canvas of={TextareaStories.Sizes} />

| state | looks | set by |
| --- | --- | --- |
| default | `--border-control` border | — |
| focused | `--cloud-blue` border, 2px thick (an inset shadow) | focus, by mouse or keyboard |
| invalid | `--state-error` border, also while focused | `invalid`, or a field's `error` |
| disabled | 50% opacity; cannot be focused, edited or submitted | `disabled` |
| read-only | looks like default; can be focused, selected and submitted, not edited | native `readOnly` |

## behaviour and keyboard

the component renders a native `<textarea>`, so the browser provides the keyboard model.

| key | does |
| --- | --- |
| `tab` / `shift+tab` | moves focus to / from the field. `tab` does not type a tab character. |
| `enter` | starts a new line. it never submits the form. |
| arrows, `home`, `end` | move the caret; with `shift` they select. |

- the component holds no state. use `defaultValue`, or `value` with `onChange`.
- no character count is built in. native `maxLength` stops typing at the limit and cuts pasted text without a word. state the limit in the hint, and show a count, linked with `aria-describedby`, when people are likely to reach it.

## accessibility

- give it a visible label: a [field](?path=/docs/components-inputs-field--docs) renders a `<label for>` and links the hint or error with `aria-describedby`. a placeholder is not a label.
- `invalid` sets `aria-invalid="true"` and turns the border `--state-error`. say in words what is wrong; for structured text, name the line: `line 2: name is empty`.
- a `maxLength` is not announced. put the limit in the hint, so it is read with the field.
- focus shows in the border (`--cloud-blue`, 2px), not with the `--focus-ring` outline.
- today: there are no forced-colours (windows high contrast) styles. the textarea removes the browser's focus outline and shows focus with a border colour and an inset shadow, which forced colours override, so a focused textarea can look unfocused there.

## content

- **label** — a noun for what goes in: `release notes`, `description`, `manifest`.
- **placeholder** — an example of a first line, or nothing. instructions go in the hint, where they stay visible while people type.
- **hint** — what the text is for and its limit: `shown on the release page. up to 500 characters.`
- **error** — what is wrong and where: `line 3: replicas must be a number`.

## do and don't

<DoDont>
  <Do caption="the limit in the hint is read with the field and stays while people type." column>
    <Field label="release notes" hint="shown on the release page. up to 500 characters.">
      <Textarea rows={3} maxLength={500} />
    </Field>
  </Do>
  <Dont caption="an instruction in the placeholder vanishes on the first keystroke." column>
    <Textarea
      aria-label="release notes"
      rows={3}
      placeholder="write the notes for the release page here, up to 500 characters"
    />
  </Dont>
</DoDont>

<DoDont>
  <Do caption="one line of text is an input." column>
    <Field label="host">
      <Input placeholder="api.example.com" />
    </Field>
  </Do>
  <Dont caption="a textarea for one value invites line breaks the value cannot hold." column>
    <Field label="host">
      <Textarea rows={2} placeholder="api.example.com" />
    </Field>
  </Dont>
</DoDont>

## props

`Textarea` passes every native `<textarea>` attribute through (`value`, `onChange`, `maxLength`, `name`, `aria-*`, …) and forwards its ref to it.
