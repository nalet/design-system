## implementation notes

- It renders a `<div>` around a `<div role="tablist">`.
- Each tab is a `<button type="button">` with `role="tab"` and `aria-selected`.
- Only the selected tab has `tabindex="0"`, and the others have `-1`, so the row is a single tab stop.
- `Tabs` renders no panel, no IDs and no `aria-controls`.
- Give your panel `role="tabpanel"` and name it after the selected tab with `aria-label`. When it holds nothing focusable, also give it `tabIndex={0}`, so keyboard users can still reach it. The with-panel story does this.
- A disabled item is a disabled `<button>`, so it leaves the tab order and the arrow keys skip it.
- A focused tab shows a 2px `--focus-ring` outline on `:focus-visible`, inside the tab.
- The labels are lowercased with `text-transform`, so the DOM keeps the text as you wrote it.
- Today: `aria-label` and other attributes go on the wrapper `<div>`, not on the tablist, so the tablist can't be named.
- Today: the tabs have no IDs, so a panel can't point at its tab with `aria-labelledby`.
- Today: a `value` that matches no item leaves every tab at `tabindex="-1"`, and the row can't be reached with `tab`.
- Other `<div>` attributes and the `ref` reach the wrapper around the tablist.

| key | does |
| --- | --- |
| `tab` | Moves focus into the row, onto the selected tab (the only one with `tabindex="0"`), and out of the row on the next press. |
| `→` / `←` | Selects the next / previous enabled tab, wrapping at the ends. It calls `onChange` and moves focus to that tab. |
| `enter` / `space` | Selects the focused tab, as a native button does. |
| `home` / `end` | Selects and focuses the first / last enabled tab. |
