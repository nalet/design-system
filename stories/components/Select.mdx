## implementation notes

- It renders a native `<select>` inside a box (a `<div>`), so the browser and the operating system provide the list and the keyboard behaviour.
- The chevron is an SVG in an `aria-hidden` span over the box's right padding, with `pointer-events: none`. Today: the padding is outside the native `<select>`, so a click on the chevron lands on the box and doesn't open the list.
- You can give the options as an `options` array (`label`, `value` and an optional `disabled`) or as `<option>` children. If you pass both, `options` wins and the children are ignored.
- The component holds no state of its own. Use `defaultValue`, or `value` with `onChange`.
- `onChange` can fire on every arrow press while the list is closed, so only store the value in it.
- A [field](?path=/docs/components-inputs-field--docs) renders a `<label for>` for it, so the select is named by the field's label.
- `invalid` sets `aria-invalid="true"` and the `--state-error` border. A field's `error` sets `invalid` for you.
- An empty first option has `value: ''`. Pass `required` with it, so the form can't be sent until someone makes a choice.
- `className` lands on the box. Every other attribute (`value`, `onChange`, `name`, `required`, `aria-*`, `style`) and the ref land on the native `<select>`.
- The box always fills its container, so set the width on the container.
- Today: a select holds one value only. The box has a fixed height, so `multiple` is not supported.

On a tv:

- The select looks for `data-nc-screen` on its ancestors when it is pressed; the nearest one counts. Only `"tv"` changes how it opens.
- It is still the native `<select>`, and still the form control: the list sets its `selectedIndex` and dispatches `input` and `change`, so `value`, `defaultValue`, `onChange`, `name`, `required` and the ref work as they do everywhere. Picking the value that is already set fires nothing.
- The select has `aria-haspopup="listbox"`, `aria-expanded` and, while the list is open, `aria-controls`.
- The list is a `<div role="listbox">`, portaled to `document.body` over a layer that dims the page and leaves a window on the select. Its rows are read from the select's `<option>`s when it opens: `role="option"`, `aria-selected` on the one that is set, `aria-disabled` on a disabled one (or one in a disabled `<optgroup>`); groups are not drawn.
- The list is named after the select: its `aria-labelledby`, its `aria-label`, or the text of its `<label>` (a field's). With none of them it takes `select.options` from the page's words (“options”).
- Opening moves the focus to the row of the value that is set; closing moves it back to the select.
- The keys the list takes are stopped (`preventDefault` and `stopPropagation`): a dialog around the select doesn't close on the `esc` that closed the list, and an app's own focus movement doesn't act on the same arrow key.
- While the list is closed, the four arrow keys are prevented from stepping through the values, and still bubble to the app. A `keydown` or `mousedown` handler of your own runs first; call `preventDefault()` in it and the select leaves the event alone.
- The list is placed 4px under the select, or above it where there is no room below, and stays 48px from the left and right edges of the window and 27px from its top and bottom: the tv's safe area. All of these grow with the page's text size.
- The remote's back key has to arrive as `Escape`, as it does for the modal and the action menu. Some tvs send another key for it: map it in your app.

| key, on a tv | does |
| --- | --- |
| `enter` or `space` on the select | Opens the list, with the focus on the value that is set. |
| `↑` / `↓` in the list | Move by one row, stopping at the first and the last; disabled rows are passed over. Nothing is picked. |
| `home` / `end` in the list | Go to the first / last row. |
| `enter` or `space` in the list | Picks the focused row, closes the list and returns the focus to the select. |
| `esc` in the list | Closes the list without picking, and returns the focus to the select. |
| `←` / `→` / `tab` in the list | Stay in the list. |
| `↑` `↓` `←` `→` on the closed select | Change nothing. |

| key | does |
| --- | --- |
| `tab` / `shift+tab` | Moves focus to / from the select. |
| `space` or `alt+↓` | Opens the list. Which of the two works depends on the platform. |
| `↑` / `↓` | Move through the options. On some platforms this changes the value without opening the list. |
| Letters | Jump to the next option that starts with what you type. |
| `enter` | With the list open, chooses the highlighted option. |
| `esc` | Closes the list without choosing. |

## props

The size prop is called `selectSize` because `size` is already a native attribute of `<select>`: the number of rows shown at once.
