## implementation notes

- `Portal` renders, in order: an optional title bar, then `favorites`, then its children (the `TileGroup`s), then the empty state and a visually hidden polite live region with the match count.
- The title bar holds the title, an `<h1>` with an 18px chevron, and the search: a `role="search"` landmark around a text input named by `searchLabel` (“search apps” by default).
- The search is uncontrolled by default. To control it, pass `query` with `onQueryChange`.
- `onQueryChange` fires on every keystroke either way.
- A controlled `query` without `onQueryChange` freezes the search box.
- The search matches against each tile's `data-nc-search`, which `Tile` sets to its title and description, lowercased.
- Tiles that don't match are hidden with the `hidden` attribute, and so is a group left without a match.
- A hidden tile never keeps the tab stop, so `tab` always lands on a tile people can see.
- Pressing `/` with focus in the body moves focus to the search.
- `esc` in the search clears it and moves focus to the first tile.
- `navigation="roving"` (the default) runs one roving-grid model across every tile in the body, favourites included, so the arrow keys move across all groups.
- The model is `useRovingGrid(ref, enabled)`, which the library exports, so a custom launcher can reuse it. It keeps one `[data-nc-tile]` element under `ref` at `tabindex="0"` and the rest at `-1`, and returns the `onKeyDown` handler for the container.
- `navigation="tab"` turns the model off. Each tile group then runs its own model, unless you give it `navigation="tab"` too.
- `density="compact"` tightens the spaces: 16px under the title bar instead of 24, and 24px between groups instead of 32.
- `Portal` passes other attributes and its `ref` to its root `<div>`.
