# icon button

a square action that shows only an icon. it has the variants and sizes of [button](?path=/docs/components-actions-button--docs); `label` is required and becomes its accessible name.

<Canvas of={IconButtonStories.Playground} />

## when to use

- in dense places where a text label does not fit: a toolbar, a card or panel header, a table row (one or two actions there; more go into an [action menu](?path=/docs/components-actions-action-menu--docs)).
- for actions people recognise from the icon alone: copy, refresh, close, delete.
- next to a field or a title, for a small action on it: copy a value, open a log.

## when not to use

- **when there is room for a label, or it is the main action of the screen.** use a [button](?path=/docs/components-actions-button--docs) with a label, and the icon in `leading` if it helps. a word is read faster than an icon is decoded.
- **for an on/off setting.** use a [switch](?path=/docs/components-inputs-switch--docs). the icon button has no pressed look.
- **for more than three or four actions side by side.** put them in a [toolbar](?path=/docs/components-actions-toolbar--docs) and let the rest overflow into an [action menu](?path=/docs/components-actions-action-menu--docs).
- **for several actions on every row of a table.** use one action menu per row and a selection toolbar for bulk actions — see [selection and bulk actions](?path=/docs/patterns-selection-and-bulk-actions--docs).
- **to go somewhere.** navigation is a link (`<a href>`), not a button. a button that changes the url breaks open-in-new-tab and the browser's back.

## anatomy

1. **container** — square (`border-radius: 0`), 1px border, 28 × 28 / 34 × 34 / 42 × 42px by size. the icon sits in the centre.
2. **icon** — the child you pass. the button does not size it: the `Icon` default of 16px suits `md`, and the sizes example pairs 12px with `sm` and 20px with `lg`. while `loading`, a spinner replaces it (12px in `sm`, 14px otherwise).
3. **label** — not drawn. `label` becomes `aria-label` and the native `title`.

## variants and states

the four variants of button. only `primary` is filled.

| variant | looks | use for |
| --- | --- | --- |
| `primary` | `--cloud-blue` fill, dark icon, lighter blue on hover | the one emphasized action of a toolbar or panel |
| `default` | `--surface` fill, `--border-2` hairline; `--surface-2` and a `--cloud-blue` border on hover | a standalone icon action |
| `ghost` | no fill or border until hover; icon in `--fg-2`, `--fg` on hover | rows of actions in a toolbar or a table row |
| `danger` | `--signal-amber` outline and icon, amber fill on hover | an action that deletes or cannot be undone |

three sizes: `sm` (28px) for table rows and dense toolbars, `md` (34px, default), `lg` (42px) beside a large input or button. match the height of the controls next to it.

`loading` swaps the icon for a spinner, disables the button and sets `aria-busy`; the size does not change. `disabled` dims it to 45% and takes it out of the tab order.

in a toolbar, keep the actions `ghost`, with at most one `primary`.

## behaviour and keyboard

the component renders a native `<button>`, so the browser provides the keyboard model.

| key | does |
| --- | --- |
| `tab` / `shift+tab` | moves focus to / from the button. a focused button shows a 2px `--focus-ring` outline, 1px outside its border. |
| `enter` / `space` | activates it. |

- `type` defaults to `"button"`, not the browser's `"submit"`. pass `type="submit"` when it submits a form.
- a disabled or loading button ignores clicks and cannot be focused.
- on mouse hover the browser shows its own `title` tooltip after a delay. it never shows on keyboard focus or touch.

## accessibility

- `label` is required by the type and becomes `aria-label`: it is the whole accessible name. write it as you want it read.
- the same text is set as `title`. assistive tech may expose it a second time as the description, and the tooltip it draws is unstyled and appears only on mouse hover.
- sighted keyboard and touch users never see the label. use icons whose meaning is not in doubt, or a [button](?path=/docs/components-actions-button--docs) with a visible label.
- the icon is decoration: `Icon` hides itself from assistive tech, and `label` names the action.
- `loading` sets `aria-busy="true"`. the spinner has `role="status"` and the name `loading`, but it appears with no text in it, so screen readers may not announce it. when the outcome matters, announce it elsewhere, e.g. with a [toast](?path=/docs/components-feedback-status-toast--docs).
- today: `loading` disables the native button, and a focused button that becomes disabled can lose focus. keyboard and screen-reader users who pressed it can be moved off it while it loads.
- today: there is no pressed state. `aria-pressed` passes through to the button but nothing changes on screen; use a [switch](?path=/docs/components-inputs-switch--docs) for on/off.
- today: don't wrap it in a [tooltip](?path=/docs/components-overlays-tooltip--docs). the tooltip's trigger is its own focusable span, so the pair takes two tab stops, the description lands on the span instead of the button, and the native `title` still appears.

## content

- `label` is an action, verb first, lowercase: `restart worker`, `copy link`, `delete volume`. never the icon's name (`arrow`, `trash`).
- when the button repeats on every row or card, name the object: `delete api-7f9c`, not `delete`. otherwise a screen reader's list of buttons is a column of identical names.
- one icon, one meaning, everywhere. an icon that stands for two actions can no longer be read as either.

## props

`IconButton` also passes every native `<button>` attribute through (`onClick`, `type`, `aria-*`, …) and forwards its ref. a `title` or `aria-label` you pass replaces the one made from `label`.
