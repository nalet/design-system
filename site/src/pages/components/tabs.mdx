# tabs

a row of mono tabs that switch between views of the same object. the selected tab is underlined in `--cloud-blue`.

<Example label="tabs and the view they switch, live">
  <WithPanel client:visible />
</Example>

## when to use

- to switch between views of one object at the same level: the `overview`, `logs`, `metrics` and `events` of one service.
- when each view makes sense on its own and people move between them in no fixed order.
- for two to six short labels that fit on one row.

## when not to use

- **to filter one list.** use <C slug="filter-tabs" />: each tab is a count over a label, and the list below follows the choice.
- **to go to another page or app.** use links; for a home page of apps, <C slug="tile">tiles</C> in a <C slug="tile-group" />.
- **for more views than fit on one row.** today the row doesn't scroll, wrap or overflow into a menu. use a <C slug="select" />.
- **to turn a setting on or off.** use a <C slug="switch" />.

## anatomy

1. **tab list** — a row with a 1px `--border` rule underneath.
2. **tab** — jetbrains mono 500, 13px, 8px × 12px padding, `--fg-muted`, shown lowercase.
3. **selection** — the selected tab's label and a 2px underline in `--cloud-blue`, laid over the list's rule.
4. **panel** — not part of the component. it goes right below the list; what it needs is under [accessibility](#accessibility).

## variants and states

| state | looks |
| --- | --- |
| rest | `--fg-muted` label |
| hover | `--fg` label |
| selected | `--cloud-blue` label and 2px underline |
| focus | a 2px `--focus-ring` outline inside the tab |
| disabled | 40% opacity. it can't be focused, clicked or reached with the arrow keys |

## behaviour

- a click selects the tab.
- the row is one tab stop, on the selected tab; the arrow keys move along it and select as they go, wrapping at the ends.
- selection follows the arrow keys: every press switches the view. keep the views quick to switch, or load a slow one only after the selection has settled.

the keyboard map and the attributes it sets are on its [react page](/design-system/react/?path=/docs/components-navigation-tabs--docs).

## accessibility

- screen readers hear a tab list, its tabs, and which one is selected.
- the panel is yours to name: name it after the selected tab, and when it holds nothing focusable, make it a tab stop, so keyboard users can reach its content. the example at the top does this.

today:

- disabled tabs can't be focused, so screen-reader users don't learn that they exist.

## content

- one or two words per tab, nouns: `overview`, `logs`, `metrics`. no verbs and no counts — a count belongs in <C slug="filter-tabs" />.
- the same views in the same order on every object of a kind, so `logs` is always in the same place.
- write labels as they should be read; the lowercase look is css.
