## implementation notes

- it is a native checkbox with `role="switch"`: a `<label>` around the track and the label text, and the native `<input type="checkbox" role="switch">` over the track, transparent. it takes the focus, the clicks and the form value, and the browser provides the keyboard model.
- `role="switch"` is what makes screen readers announce a switch. the state is the native `checked`: don't add `aria-checked`.
- the component holds no state. use `defaultChecked`, or `checked` with `onChange`. apply the setting in `onChange`.
- focus is drawn on `:focus-visible`.
- `enter` does not toggle it, as with any native checkbox.
- `className` lands on the outer `<label>`; every other attribute — `checked`, `defaultChecked`, `onChange`, `name`, `aria-*` — and the ref land on the native `<input type="checkbox" role="switch">`.
- today: inside a [field](?path=/docs/components-inputs-field--docs) with `error`, react warns about an unknown `invalid` attribute.

| key | does |
| --- | --- |
| `tab` / `shift+tab` | moves focus to / from the switch. |
| `space` | toggles it. |
