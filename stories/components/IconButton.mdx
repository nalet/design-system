## implementation notes

- It renders a native `<button>`, so the browser gives it the keyboard behaviour for free.
- `type` defaults to `"button"`, not the browser's `"submit"`, so it doesn't send a form by accident. Pass `type="submit"` when it submits a form.
- `label` is required by the type, and becomes the `aria-label` and the native `title`, so the button always has a name and a tooltip.
- A `title` or `aria-label` you pass replaces the one made from `label`.
- The icon is the child you pass, such as `<Icon icon={RotateCw} />`.
- The button doesn't size the icon. The `Icon` default of 16px suits `md`, and the sizes example passes `size={12}` with `sm` and `size={20}` with `lg`.
- `loading` swaps the icon for a spinner, disables the button and sets `aria-busy="true"`. The size doesn't change.
- The spinner has `role="status"` and the name `loading`, but it appears with no text in it, so screen readers may not announce it.
- `disabled` dims it to 45% and takes it out of the tab order.
- A disabled or loading button ignores clicks and can't be focused.
- A focused button shows a 2px `--focus-ring` outline, 1px outside its border, on `:focus-visible`, so the ring shows for keyboard focus and not for a click.
- Every native `<button>` attribute passes through, such as `onClick`, `type` and `aria-*`, and the `ref` reaches the `<button>`.
- Today: `aria-pressed` passes through to the button, but nothing changes on screen.

| key | does |
| --- | --- |
| `tab` / `shift+tab` | Moves focus to / from the button. |
| `enter` / `space` | Activates it. |
