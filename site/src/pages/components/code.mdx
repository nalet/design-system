# code

Code shows what people type or copy, such as a command, a flag or a file name, in <Term id="monospace">monospace</Term>. By default it sits inside a sentence; it can also stand on its own, as a block.

<Example label="inline code in a sentence">
  <Inline />
</Example>

## when to use

- Inside a sentence, for what people type or copy: a command such as “ctl get volumes”, a flag such as “--replicas=0”, a file name or a setting.
- As a block, for a command people copy and run, a few lines of configuration, or a command with its output.

## when to use something else

- **For a key on the keyboard.** Use a <C slug="kbd">keycap</C>, such as <Kbd>enter</Kbd>.
- **For values in monospace that people read rather than type**, such as durations, sizes and hashes in a list or a table cell. Use <C slug="text">mono text</C>: monospace, with no frame and no colour. A column of framed cyan cells is noise.
- **For emphasis.** Cyan pulls the eye, so keep it for code. To make a word stand out in a sentence, use <C slug="text">interface text</C>.

## anatomy

Inline:

1. **Frame.** A thin border on a darker shade of the <Term id="canvas">canvas</Term>, close around the text, with square corners.
2. **Text.** Monospace, in cyan.

Block:

1. **Frame.** A thin border on the same darker shade, with room around the text and no space outside it. It scrolls sideways.
2. **Text.** Monospace, in light grey. Spaces and line breaks are kept as written. Long lines scroll, and never wrap.

## variants and states

Inline code sits in running text. It wraps with the sentence, at its spaces, so keep it short.

A block shows several lines exactly as written. It has no maximum height and grows with its content, so show a few lines, not a whole log.

</Example>

A long line scrolls inside the block instead of wrapping.

Blocks can follow one another.

There is no syntax highlighting, so all the code is in one colour. There are no line numbers, no copy button and no way to wrap long lines either.

## behaviour

- Inline code, and a block that fits, aren't a <Term id="tab-stop">tab stop</Term>.
- A block whose lines run past its edge becomes a tab stop of its own while it overflows: <Kbd>tab</Kbd> reaches it, and the arrow keys scroll it.
- The text in both forms can be selected and copied like any other text.

The full keyboard map is on the [React page](/design-system/react/?path=/docs/components-data-display-code--docs) for code.

## accessibility

- Most <Term id="screen-reader">screen readers</Term> read the text without saying “code”.
- A block keeps its line breaks, and screen readers read it line by line.
- A block that scrolls has a name of its own, its <Term id="accessible-name">accessible name</Term>, and that name is “code” unless you give it a better one. Name it after what it holds: “install command”.
- The cyan of inline code and the light grey of a block both have plenty of <Term id="contrast">contrast</Term> on their background.
- Symbols are read out as they are. The prompt, the “$” a terminal shows before a command, is read as “dollar”. Leave it out of commands people copy.

## content

- Show the command exactly as it runs, with real flags. Use made-up names and hosts: “api-7f9c”, “storage-01”, “example.com”.
- A command people copy has no prompt. When you show a command with its output, mark the typed line with “$”, so the two read apart.
- Inline code is one word, or something just as short, such as a flag. A command longer than a few words gets a block.
- Don't put a sentence in code.

## specs

| form | in code | frame | text |
| --- | --- | --- | --- |
| Inline | `<Code>`, the default: a `code` element | A 1px `--border`, a `--bg-2` fill, padding 1px 6px, `border-radius: 0` | JetBrains Mono 13px, line height 1.5, `--cloud-cyan` |
| Block | `<Code block>`: a `pre` with a `code` inside | A 1px `--border`, a `--bg-2` fill, padding 12px 16px, no margin, `border-radius: 0`, `overflow-x: auto` | JetBrains Mono 13px, line height 1.5, `--fg-2`; `white-space: pre` keeps spaces and line breaks, and long lines scroll |

- **A block that overflows:** while its lines run past its edge, it is a focusable region (`tabindex="0"`, `role="region"`, named “code”). Pass an `aria-label`, such as “install command”, to name it better. Keyboard focus: a 2px `--focus-ring` outline, 2px outside the frame.
- **Contrast:** `--cloud-cyan` on `--bg-2` is about 6.6:1; block text in `--fg-2` is about 12:1.
- **Mono text:** `<Text variant="code">`, for values people read, without a frame.
- **Interface text:** `<Text variant="ui">`, for emphasis in a sentence.
