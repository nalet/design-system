# table

A hairline-grid table for reading records: mono cells, lowercase mono headers, no zebra. It shows rows; it doesn't sort, select or navigate them — that's the <C slug="data-table" />.

<Example column label="a table of workloads">
  <Basic />
</Example>

## when to use

- To show a short, read-only set of records with the same fields, so people can compare values down a column: workloads, volumes, recent runs.
- When every row fits on the screen and nobody needs to sort, select or act on the rows.
- As the body of a panel: a <C slug="card" /> with `flush`.

## when not to use

- **For a list people work through** — sorting, selecting rows, grouping, loading more, moving between rows with the keyboard. Use the <C slug="data-table" />; this table has none of that, and adding it on top is how keyboard and screen-reader support gets lost.
- **For a screen whose job is to find items and act on them.** That's a [worklist](/design-system/patterns/worklist/): a filter bar, a data table and a toolbar.
- **For layout.** A table announces rows and columns, which means nothing for a form. Lay forms out with a <C slug="stack" /> — see [forms and settings](/design-system/patterns/forms-and-settings/).
- **For the fields of one record.** One row with many columns reads badly and scrolls sideways. List label and value pairs in a <C slug="card" />.

## anatomy

1. **Scroll frame** — 1px `--border` on every side, full width. A table wider than its frame scrolls sideways inside it.
2. **Header row** — on `--bg-2`. Each column header: JetBrains Mono 600, 11px, letter-spacing 0.04em, `--fg-muted`, shown lowercase, never wraps. Padding 8px 12px, 1px `--border` below.
3. **Body row** — on hover its cells tint to `--surface-2`. The last row drops its bottom rule; the frame closes it.
4. **Cell** — JetBrains Mono 13px, `--fg-2` on `--surface`, padding 12px, vertically centered, 1px `--border` below.
5. **Empty row** (with no rows) — one cell across every column: mono 12px, `--fg-dim`, centered, padding 24px 12px.

## behaviour

- The table takes no focus itself; what you put in its cells does. `tab` moves through the links and buttons in the cells, in reading order.
- Rows tint on hover but do nothing on click. There is no row selection, row action or sorting.
- While a table is wider than its frame, the frame is a stop of its own: `tab` reaches it, and the arrow keys scroll it sideways.

The keyboard map and the attributes it sets are on its [React page](/design-system/react/?path=/docs/components-data-display-table--docs).

## accessibility

- The markup is a real table, so screen readers' own table commands work: move by cell, row and column, and hear each cell with its column header.
- **Name every table**, by the heading above it or with a label of its own.
- Headers are lowercased by CSS only. Screen readers read the text as you wrote it, so write it the way it should be read.
- A row header — a first cell that names the row — needs the table built from its parts. Today that cell takes the header look (11px muted mono, 8px 12px padding) and keeps its bottom rule in the last row.
- Colour in a cell is never announced. Say a state in words, with <C slug="object-status" />.
- A frame that scrolls is named like its table, and shows the focus ring when it has focus. Keep tables narrow enough to fit where you can, and put the columns that matter first.
- Changes to the rows are not announced. When rows change because of something the user did, say what happened — see [message handling](/design-system/patterns/message-handling/).

## content

- Headers: a lowercase noun, one or two words — `workload`, `size`, `last run`. Put the unit in the header, `cpu (cores)`, not in every cell.
- Right-align numbers and give them the same number of decimals down a column, so the digits line up.
- The empty text says what is missing, in the table's own words: `no workloads in this project`, not `no data`.
- A failed load is not an empty table. Show the error in a <C slug="message-strip" /> above it. When an empty table needs an explanation or a next step, see [empty states](/design-system/patterns/empty-states/).
