import { useState } from 'react';
import { Meta } from '@storybook/addon-docs/blocks';
import { Button, DataTable, FilterBar, IllustratedMessage, formatCount } from '../../src';
import { DoDont, Do, Dont, Example } from '../_blocks';
import { code, makeBacklog } from '../_data/backlog';
import { BACKLOG_COLUMNS } from '../_data/status';

export const ROWS = makeBacklog().filter((b) => b.kind === 'series').slice(0, 12);

export const NoMatches = () => {
  const [q, setQ] = useState('lantern');
  const needle = q.trim().toLowerCase();
  const rows = needle ? ROWS.filter((b) => `${b.title} ${code(b)}`.toLowerCase().includes(needle)) : ROWS;
  return (
    <div style={{ display: 'grid', gap: 'var(--s-3)', width: '100%' }}>
      <FilterBar
        search={{ value: q, onChange: setQ, placeholder: 'search titles', label: 'search titles' }}
        resultCount={needle ? `${formatCount(rows.length)} of ${formatCount(ROWS.length)}` : undefined}
        onClearAll={() => setQ('')}
      />
      <DataTable
        aria-label="missing episodes"
        columns={BACKLOG_COLUMNS}
        rows={rows}
        rowKey={(b) => b.id}
        empty={
          <IllustratedMessage
            illustration="search"
            size="sm"
            headingLevel={2}
            title="no matches"
            description={`nothing in this list fits “${q.trim()}”. clear the search, or try another word.`}
            actions={<Button size="sm" onClick={() => setQ('')}>clear filters</Button>}
          />
        }
      />
    </div>
  );
};

# empty states

what a list, a panel or a page shows when it has nothing to show: a line illustration, a title that says what is true, a description that says why and what to do, and at most one primary action.

<Example column label="a search that matches nothing, live">
  <NoMatches />
</Example>

## when to use

- when a list, a table or a page has no items to show, and saying why helps: nothing yet, nothing left to do, nothing matches, it couldn't load, it can't be told yet.
- in the place of the content: in a data table's body, in a worklist under its filter bar, or as the whole page.

## when not to use

- **while the content is loading.** use `loading` on the [data table](?path=/docs/components-data-display-data-table--docs), or a [spinner](?path=/docs/components-feedback-status-spinner--docs). an empty state before the load has finished says something that isn't known yet.
- **for a problem with content that is still on screen** — a refresh failed, an action failed, 105 titles can't be checked. that's a [message strip](?path=/docs/components-feedback-status-message-strip--docs) above the content; see [message handling](?path=/docs/patterns-message-handling--docs).
- **to confirm an action** ("8 episodes queued"). that's a [toast](?path=/docs/components-feedback-status-toast--docs).
- **for one empty value in a row.** the cell says it: a [date cell](?path=/docs/components-data-display-table-cells--docs) shows a dash that is read "no date".
- **for a short read-only table with no rows.** the [table](?path=/docs/components-data-display-table--docs)'s own `empty` line is enough.

## anatomy

<Example column label="the parts of an empty state">
  <IllustratedMessage
    illustration="search"
    headingLevel={3}
    title="no matches"
    description="nothing in this list fits the search and filters. clear them to see every episode again."
    actions={<Button>clear filters</Button>}
  />
</Example>

1. **region** — where the content would be: the data table's body (its `empty` prop), a worklist's body in place of the table, or the page. the empty state takes the content's place, not the frame's: the page header, the tabs and the filter bar stay, so people can change what made the list empty.
2. **illustration** — `illustration`: one line drawing per kind, on a 160 × 120 grid, 160px wide at `md`, 96px at `sm` and 220px at `lg`, with square-capped lines 1.5px wide at `md`. the frame is in `--border-control`, soft lines in `--border-2`, and an accent by kind: `--cloud-blue` for `empty` and `search`, `--state-success` for `done`, `--state-error` for `error`, `--state-warning` for `unknown`. it is decoration, hidden from assistive tech.
3. **title** — `title`: a real heading, an `h2` unless `headingLevel` says otherwise. jetbrains mono 600, 16px (14px at `sm`, 22px at `lg`), line-height 1.3, `--fg`, lowercase.
4. **description** (optional) — `description`: inter 13px, line-height 1.55, `--fg-muted`, at most 46 characters wide, 8px under the title.
5. **action** (optional) — `actions`: at most one primary [button](?path=/docs/components-actions-button--docs), and an optional secondary one. centred, 8px apart, 16px under the text.

all of it is one [illustrated message](?path=/docs/components-feedback-status-illustrated-message--docs) (`IllustratedMessage`), centred, with padding 32px 16px at `md`, 16px 12px at `sm` and 64px 16px at `lg`, and 16px under the picture (12px at `sm`, 24px at `lg`).

## behaviour

### the five kinds

| kind | says | the picture | its action |
| --- | --- | --- | --- |
| `empty` | nothing is here yet | a prompt with nothing typed after it | the step that adds the first item |
| `done` | nothing is left to do: good news | the prompt, and a check | usually none |
| `search` | the search or the filters match nothing | rows, and a square lens that finds none | `clear filters` |
| `error` | the content could not be loaded | a line that doesn't connect | `try again` |
| `unknown` | it can't be told yet | a question that can't be answered yet | the action that resolves it |

### which kind

pick the kind by what is true, not by what the screen looks like. that is honest status: a list that failed to load, or can't be checked yet, is not done.

| situation | kind | title | action |
| --- | --- | --- | --- |
| nothing has been added yet: a new list, a first visit | `empty` | `nothing tracked yet` | the step that adds the first item, primary: `import a list` |
| items exist, but none is due yet (a "not yet aired" tab) | `empty` | `132 not yet aired` | none |
| the work is done: nothing is left to act on | `done` | `nothing missing` | none |
| a tab or a filter of the list, and that slice is done | `done` | `nothing needs attention` | none |
| the search or the filters match nothing, but the list has items | `search` | `no matches` | `clear filters` |
| the list could not be loaded, and there is nothing older to show | `error` | `couldn't load the list` | `try again` |
| it can't be told yet: a check hasn't run, the holdings are unknown | `unknown` | `nothing can be checked yet` | the action that resolves it, primary: `ask the catalog again` |
| the list is still loading | no empty state | — | `loading` on the [data table](?path=/docs/components-data-display-data-table--docs), or a [spinner](?path=/docs/components-feedback-status-spinner--docs) |
| a refresh or an action failed, and the content is still on screen | no empty state | — | a [message strip](?path=/docs/components-feedback-status-message-strip--docs) above it, with a way forward |

### where it goes

- **in a data table** — its `empty` prop: the message sits in the body, under the header row, in one cell across every column. use `size="sm"`.
- **in a worklist** — in place of the table, at `md` (the default), under the [worklist](?path=/docs/patterns-worklist--docs)'s tabs and filter bar. leave the selection toolbar out while the list is empty: there is nothing to select or act on.
- **as the page** — `size="lg"`, when the whole page has nothing to show.
- the title's heading level follows the page around it: an `h2` under the page's `h1`, an `h3` inside a section that has an `h2`. `headingLevel` sets it.

### what happens next

- the action works in place. "clear filters" clears them and the list comes back. "try again" loads again; show `loading` while it runs. the `unknown` action starts what resolves it, and says so in a [toast](?path=/docs/components-feedback-status-toast--docs): "asking the catalog again — the list follows".
- the empty state goes as soon as there are items to show.
- the filter bar stays while a search matches nothing, so people can change a word instead of starting over.
- never show an empty state before the content is known. a table given `empty` shows it whenever it has no rows, even while `loading`, so pass `empty` only once the load has finished.

## keyboard and accessibility

- the title is a real heading, so people can find the message by its heading. set `headingLevel` so it fits the page's outline.
- the picture is decoration (`aria-hidden`). the title and the description carry the meaning, never the picture or its colour.
- the message is not a live region: it isn't announced when it appears. say the change where people are. the [filter bar](?path=/docs/components-inputs-filter-bar--docs)'s result count is a polite live region: pass `resultCount`, and "0 of 12" is announced as the search empties the list.
- the action is a native button, in the tab order where the message sits; `enter` and `space` press it.

today:

- pressing the action usually removes the message, and the button with it, so focus falls to the page body: after "clear filters", nothing has focus. move focus yourself, to the search field for instance.
- the illustrated message doesn't hold you to one primary action: `actions` renders whatever it is given.

## content

- **title** — what is true, in the list's own words, in a few words: `nothing missing`, `no matches`, `couldn't load the list`, `nothing can be checked yet`, `nothing tracked yet`. never `no data`, `empty`, `oops` or `error`.
- **description** — why, and what to do, in one or two sentences: `every aired episode is in the library.`, `nothing in this list fits the search and filters.`
- **action** — a verb and its object: `clear filters`, `try again`, `import a list`, `ask the catalog again`.
- **counts** — when they help: `132 not yet aired`.
- **no technical detail** — no codes, ids or raw errors in the title or the description. when people need them, they go in a [message strip](?path=/docs/components-feedback-status-message-strip--docs)'s details.
- **good news is plain** — `nothing needs attention`. no celebration, no apology.
- **no blame** — `nothing tracked yet`, not `you haven't added anything`.
