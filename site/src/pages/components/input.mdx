# input

A square, single-line text field in mono type. Put it in a <C slug="field" /> for its label, hint and error.

<Example label="an input">
  <Playground />
</Example>

## when to use

- For one line of text that people type: a name, a host, an ID, a number, a search term.
- Inside a <C slug="field" />, which gives it a visible label and wires its hint and error to it.
- With a `leading` icon or prompt when it says what kind of value goes in (a search icon, a `>` prompt), or a `trailing` unit such as `ms` or `GiB`.

## when not to use

- **For more than one line.** Use a <C slug="textarea" />. An input cannot wrap, and hides whatever scrolls out of view.
- **To pick from a known list.** Use a <C slug="select" />, so people cannot type a value that does not exist.
- **For on/off.** Use a <C slug="checkbox" /> in a form that is saved, or a <C slug="switch" /> when the change applies at once.
- **To filter a list or table.** Use the <C slug="filter-bar" />, which lays out the search, the filters and their reset.
- **To lay out a whole form or settings page.** Start from [forms and settings](/design-system/patterns/forms-and-settings/).

## anatomy

1. **Box** — square, 1px `--border-control` border on `--bg-2`; height 28 / 34 / 42px and side padding 8 / 12 / 16px by size. It fills the width of its container.
2. **Leading affix** (optional) — an icon or prompt before the text, in `--fg-dim`, 8px from the text (12px in `lg`).
3. **Text** — JetBrains Mono 13px (14px in `lg`) in `--fg`. The placeholder is `--fg-dim`.
4. **Trailing affix** (optional) — a unit or icon after the text, with the same colour and spacing.

## variants and states

Three sizes: `sm` (28px) for toolbars, filter rows and table cells, `md` (34px, the default) for forms, `lg` (42px) for a lone search or command prompt. Match the height of the buttons beside it.

## behaviour

- The input is one tab stop. People type, move the caret and select as in any text field, and `enter` can submit the form it is in.
- Today: only the text area takes clicks. A click on the box's padding or on an affix does not focus the field.

The keyboard map and the attributes it sets are on its [React page](/design-system/react/?path=/docs/components-inputs-input--docs).

## accessibility

- Give it a visible label: a <C slug="field" /> renders one, and links the hint or the error to the input so they are read with it. A placeholder is not a label: it disappears with the first keystroke.
- Where a visible label does not fit (a search box in a toolbar), give it an `aria-label`, and add a leading search icon so sighted people see what the box is for.
- An invalid input turns its border `--state-error`. The colour alone is a weak cue — about 1.6:1 against the normal border — so always say in words what is wrong. A field's error does that.
- Affixes are not part of the input's name. An icon hides itself, and text such as `ms` is not announced when the field is focused, so put the unit in the label too: `timeout (ms)`.
- Focus shows in the border (`--cloud-blue`, 2px), not with the `--focus-ring` outline of buttons and checkboxes — see [interaction](/design-system/foundations/interaction/#focus).
- A disabled field cannot be focused, so screen-reader users may never find it. When people need to read or copy the value, make it read-only instead — today it looks the same as an editable field, so say why it cannot change.
- Today: there are no forced-colours (Windows high contrast) styles. Forced colours replace border colours and remove the inset shadow, so a focused field can look unfocused there.

## content

- **Label** — a noun for the value, in sentence case, no colon: `Host`, `Release name`, `Timeout (ms)`.
- **Placeholder** — an example of a valid value, or nothing: `api.example.com`. Never the label, never an instruction: both vanish on the first keystroke.
- **Hint** — the format or the limit, in one short line: `Lowercase letters, digits and hyphens`.
- **Error** — what is wrong and how to fix it: `Use 63 characters or fewer`. Not `Invalid input`.
- **Unit** — in the label, and as a `trailing` affix when people need to see it while they type.

  </Do>
  <Dont caption="A red border alone shows that something is wrong, not what. It is also easy to miss." column>

  </Dont>
</DoDont>
