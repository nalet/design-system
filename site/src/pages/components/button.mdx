# button

a square, mono-labelled action. `primary` is the one emphasized action on a screen; every other action is `default` or `ghost`.

<Example label="the four variants">
  <Variants />
</Example>

## when to use

- to start an action on the current screen: save, run, grab, ask again.
- as the single emphasized action of a view, a toolbar or a dialog footer: the `primary` button.
- for the secondary actions beside it (`default`), and for low-weight escapes like cancel (`ghost`).

## when not to use

- **to go somewhere.** navigation is a link, not a button. a button that changes the address breaks open-in-new-tab and the browser's back.
- **for an icon with no label.** use an <C slug="icon-button" />, which requires a name.
- **for more than two or three actions in a row.** put them in a <C slug="toolbar">toolbar</C> and let the rest overflow into an <C slug="action-menu" />.
- **for an action on each row of a table.** use one action menu per row and a selection toolbar for bulk actions — see [selection and bulk actions](/design-system/patterns/selection-and-bulk-actions/).

## anatomy

1. **container** — square, a 1px border, 28, 34 or 42px high by size.
2. **leading slot** (optional) — an icon, or the spinner while the button is busy.
3. **label** — jetbrains mono 600, shown lowercase.
4. **trailing slot** (optional) — an icon after the label, hidden while busy.

## variants and states

four variants. only `primary` is filled; it is the emphasized action.

| variant | looks | use for |
| --- | --- | --- |
| `primary` | cloud-blue fill, dark label | the one emphasized action of a view or region |
| `default` | surface fill, hairline border, blue border on hover | every other action |
| `ghost` | no fill or border until hover | cancel, dismiss, low-weight actions next to a primary |
| `danger` | amber outline, amber fill on hover | an action that deletes or cannot be undone |

three sizes: `sm` (28px) for toolbars and table rows, `md` (34px, the default), `lg` (42px) for a lone call to action.

## behaviour

- a button acts on the current screen when it is pressed, with a pointer, `enter` or `space`.
- while its action runs, the button is busy: it keeps its place and its label, and a second press does nothing. say what happened afterwards, in a <C slug="toast" /> or where the result shows.
- a disabled or busy button ignores presses.
- in a form, only the button that saves submits it; every other button just acts.

the keyboard map and the attributes it sets are on its [react page](/design-system/react/?path=/docs/components-actions-button--docs).

## accessibility

- the accessible name is the label's text. the lowercase look is css, so write the label as you want it read.
- a disabled button can't be focused, so a keyboard or screen-reader user may never find it. when the reason matters ("nothing selected"), say it next to the button, or keep the button enabled and explain on press.
- icons in the slots are decoration: the label carries the meaning. an icon-only action is an <C slug="icon-button" />.
- the focus ring is the 2px `--focus-ring` outline every control shares — see [interaction](/design-system/foundations/interaction/#focus).

## content

- start with a verb, and name the object when the screen holds more than one kind: `grab 8 selected`, `ask the catalog again`, `save changes`.
- lowercase, short, no full stop, no exclamation mark.
- never `ok`, `submit`, `yes` or `click here`: say what happens.
- a count in the label keeps a bulk action honest: `grab 8 selected` rather than `grab selected`.
