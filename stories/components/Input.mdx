## implementation notes

- It renders a native `<input>` inside a box (a `<div>`), with the affixes beside it in the box.
- The text is the native `<input>`, so the browser gives it the keyboard behaviour for free.
- `type` is the browser's default, `text`, unless you pass one. `search`, `number`, `email` and `password` keep their native behaviour.
- The component holds no state of its own. Use `defaultValue`, or `value` with `onChange`.
- The native `<input>` carries the name, the value and the state.
- A [field](?path=/docs/components-inputs-field--docs) gives it a label: it renders a `<label for>` and links the hint or error with `aria-describedby`.
- `invalid` sets `aria-invalid="true"` and the `--state-error` border. A field's `error` sets `invalid` for you.
- `leading` and `trailing` take any node, such as an `<Icon icon={Search} />`, a `>` prompt or a unit like `ms`, and render it inside the box, outside the `<input>`.
- `className` lands on the box. Every other attribute, such as `value`, `onChange`, `type`, `name`, `aria-*` and `style`, lands on the native `<input>`, and so does the ref.
- Set the width on the container: the box always fills it.

| key | does |
| --- | --- |
| `tab` / `shift+tab` | Moves focus to / from the field. |
| Characters | Type into it. `←` `→` `home` `end` move the caret; with `shift` they select. |
| `enter` | Can submit the surrounding form (the browser's implicit submission). |

## props

The size prop is called `inputSize`, because `size` is already a native attribute: a width in characters.
